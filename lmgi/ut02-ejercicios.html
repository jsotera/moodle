    2.1 Validar XML con XSD en Visual Studio Code

    Actividad para comprobar cómo un editor puede ayudarnos a detectar errores de validación cuando un XML está asociado a un esquema XSD.

    Punto de partida

    Vamos a utilizar el ejemplo completo de XML y XSD que aparece en W3Schools:

    W3Schools - XML Schema Example

    En esa página se trabaja con un pedido llamado shiporder. El XML contiene datos como la persona que realiza el pedido, la dirección de envío y varios productos. El XSD define qué estructura debe cumplir ese XML.

    Preparar los archivos

    1. Crea una carpeta para la actividad.
    2. Dentro de esa carpeta, crea un archivo llamado shiporder.xml.
    3. Copia en ese archivo el XML de ejemplo que aparece en W3Schools.
    4. Crea otro archivo llamado shiporder.xsd.
    5. Copia en ese archivo el XSD de ejemplo de la misma página.

    Es importante que ambos archivos estén en la misma carpeta, porque el XML indica que su esquema se encuentra en shiporder.xsd.

    carpeta-actividad/
  shiporder.xml
  shiporder.xsd

    Relación entre XML y XSD

    Fíjate en que el XML contiene una referencia al esquema XSD:

    <shiporder orderid="889923"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:noNamespaceSchemaLocation="shiporder.xsd">

    La parte xsi:noNamespaceSchemaLocation="shiporder.xsd" indica al editor y a las herramientas de validación qué archivo XSD deben utilizar para comprobar el XML.

    Instalar extensiones en Visual Studio Code

    Abre Visual Studio Code y entra en la sección de extensiones. Instala estas extensiones:

    • XML, de Red Hat.
    • XML Tools.

    Después, abre la carpeta completa de la actividad desde Visual Studio Code. No abras solo el archivo suelto: abre la carpeta para que el editor pueda encontrar correctamente el XML y el XSD.

    Comprobar que todo funciona

    Si todo está bien configurado, Visual Studio Code debería mostrar el XML correctamente y no debería marcar errores de validación.

    Comprueba también que puedes navegar cómodamente por el XML, ver las etiquetas coloreadas y detectar la estructura del documento.

    Provocar errores de validación

    Ahora modifica el XML para comprobar si el IDE detecta los errores. Prueba, por ejemplo:

    • Cambiar el nombre de una etiqueta, por ejemplo <orderperson> por <persona>.
    • Eliminar un elemento obligatorio.
    • Cambiar el orden de los elementos dentro de <shiporder>.
    • Quitar el atributo orderid.
    • Escribir texto donde el XSD espera un número, por ejemplo en <quantity> o <price>.
    • Cambiar el nombre del archivo XSD o modificar la ruta de xsi:noNamespaceSchemaLocation.

    Observa qué errores aparecen, dónde los marca Visual Studio Code y qué información ofrece para ayudarte a corregirlos.

    Volver a dejarlo válido

    Después de probar errores, corrige el XML hasta que vuelva a ser válido. La actividad termina cuando seas capaz de:

    • Explicar qué archivo contiene los datos.
    • Explicar qué archivo contiene las reglas.
    • Identificar cómo se enlaza el XML con el XSD.
    • Provocar al menos tres errores distintos.
    • Corregir esos errores hasta que el editor deje de marcarlos.

    2.2 Generar un XML válido a partir de un XSD

    Actividad para practicar la lectura de un esquema XSD y construir un documento XML que cumpla sus reglas.

    XSD de partida

    Dado el siguiente esquema XSD, genera un documento XML válido:

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <!-- Estructura principal y tipos referenciados -->
  <xs:element name="instituto">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="aulas">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="aula" type="xs:string" maxOccurs="unbounded" />
            </xs:sequence>
          </xs:complexType>
        </xs:element>

        <xs:element name="profesores">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="profesor" type="xs:string" maxOccurs="unbounded" />
            </xs:sequence>
          </xs:complexType>
        </xs:element>

        <xs:element name="alumnos">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="alumno" type="xs:string" maxOccurs="unbounded" />
            </xs:sequence>
          </xs:complexType>
        </xs:element>
      </xs:sequence>

      <xs:attribute name="nombreCentro" type="xs:string" use="optional" />
    </xs:complexType>
  </xs:element>
</xs:schema>

    Antes de escribir el XML

    Antes de empezar a escribir, analiza el XSD y responde mentalmente a estas preguntas:

    • ¿Cuál es el elemento raíz?
    • ¿Qué elementos deben aparecer dentro de la raíz?
    • ¿En qué orden deben aparecer?
    • ¿Qué elementos pueden repetirse varias veces?
    • ¿Hay algún atributo obligatorio u opcional?

    Requisitos que debe cumplir tu XML

    • El elemento raíz debe ser <instituto>.
    • Debe contener los elementos <aulas>, <profesores> y <alumnos>.
    • Los elementos deben aparecer en el orden indicado por <xs:sequence>.
    • Dentro de <aulas> debe haber uno o varios elementos <aula>.
    • Dentro de <profesores> debe haber uno o varios elementos <profesor>.
    • Dentro de <alumnos> debe haber uno o varios elementos <alumno>.
    • El atributo nombreCentro es opcional, pero puedes incluirlo.

    Tarea

    Crea un archivo XML válido que cumpla el XSD anterior. Utiliza nombres inventados para las aulas, profesores y alumnos.

    Después, valida el XML en Visual Studio Code usando el XSD como hicimos en el ejercicio anterior.

    Comprobación adicional

    Cuando tengas un XML válido, prueba a romperlo para comprobar que el validador detecta los errores:

    • Cambia el orden de <profesores> y <aulas>.
    • Elimina todos los elementos <aula>.
    • Cambia <alumno> por <estudiante>.
    • Escribe el atributo nombreCentro en otro elemento que no sea <instituto>.

    2.3 Videojuego: complexType con una restricción

    Actividad para crear un XML válido a partir de un XSD con un complexType y una restricción sencilla.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="videojuego">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="titulo" type="xs:string" />
        <xs:element name="genero">
          <xs:simpleType>
            <xs:restriction base="xs:string">
              <xs:enumeration value="aventura" />
              <xs:enumeration value="deportes" />
              <xs:enumeration value="estrategia" />
              <xs:enumeration value="puzle" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>
      </xs:sequence>
    </xs:complexType>
  </xs:element>
</xs:schema>

    Tarea

    Genera un XML válido para este esquema. Después prueba a escribir un género que no esté en la enumeración y observa el error de validación.

    2.4 Ciudad: límites numéricos

    Actividad para crear un XML válido aplicando límites mínimos y máximos en valores numéricos.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="ciudad">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="nombre" type="xs:string" />
        <xs:element name="habitantes">
          <xs:simpleType>
            <xs:restriction base="xs:integer">
              <xs:minInclusive value="1" />
              <xs:maxInclusive value="10000000" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>
        <xs:element name="temperaturaMedia">
          <xs:simpleType>
            <xs:restriction base="xs:decimal">
              <xs:minInclusive value="-30" />
              <xs:maxInclusive value="50" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>
      </xs:sequence>
    </xs:complexType>
  </xs:element>
</xs:schema>

    Tarea

    Genera un XML válido para una ciudad. Después prueba valores fuera de rango, como 0 habitantes o una temperatura media de 80.

    2.5 Libro: mezclando enumeraciones, patrones y atributos

    Actividad para crear un XML válido combinando restricciones de texto, expresiones regulares y atributos obligatorios.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="libro">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="titulo" type="xs:string" />
        <xs:element name="isbn">
          <xs:simpleType>
            <xs:restriction base="xs:string">
              <xs:pattern value="[0-9][0-9][0-9]-[0-9][0-9][0-9]" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>
        <xs:element name="formato">
          <xs:simpleType>
            <xs:restriction base="xs:string">
              <xs:enumeration value="papel" />
              <xs:enumeration value="ebook" />
              <xs:enumeration value="audiolibro" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>
      </xs:sequence>
      <xs:attribute name="idioma" use="required">
        <xs:simpleType>
          <xs:restriction base="xs:string">
            <xs:enumeration value="es" />
            <xs:enumeration value="eu" />
            <xs:enumeration value="en" />
          </xs:restriction>
        </xs:simpleType>
      </xs:attribute>
    </xs:complexType>
  </xs:element>
</xs:schema>

    Tarea

    Genera un XML válido. Después comprueba qué ocurre si el ISBN no sigue el patrón, si falta el atributo idioma o si usas un formato no permitido.

    2.6 Torneo: repeticiones y estructuras anidadas

    Actividad para practicar elementos repetibles, atributos y estructuras internas sin usar tipos reutilizables.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="torneo">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="equipo" minOccurs="2" maxOccurs="8">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="nombre" type="xs:string" />
              <xs:element name="jugador" minOccurs="2" maxOccurs="5">
                <xs:complexType>
                  <xs:sequence>
                    <xs:element name="alias">
                      <xs:simpleType>
                        <xs:restriction base="xs:string">
                          <xs:pattern value="[A-Za-z0-9_]+" />
                        </xs:restriction>
                      </xs:simpleType>
                    </xs:element>
                    <xs:element name="nivel">
                      <xs:simpleType>
                        <xs:restriction base="xs:integer">
                          <xs:minInclusive value="1" />
                          <xs:maxInclusive value="100" />
                        </xs:restriction>
                      </xs:simpleType>
                    </xs:element>
                  </xs:sequence>
                  <xs:attribute name="capitan" type="xs:boolean" use="optional" />
                </xs:complexType>
              </xs:element>
            </xs:sequence>
            <xs:attribute name="codigo" use="required">
              <xs:simpleType>
                <xs:restriction base="xs:string">
                  <xs:pattern value="EQ-[0-9][0-9]" />
                </xs:restriction>
              </xs:simpleType>
            </xs:attribute>
          </xs:complexType>
        </xs:element>
      </xs:sequence>
      <xs:attribute name="nombre" type="xs:string" use="required" />
    </xs:complexType>
  </xs:element>
</xs:schema>

    Tarea

    Genera un XML válido con al menos dos equipos. Cada equipo debe tener entre dos y cinco jugadores. Usa al menos un atributo opcional capitan.

    2.7 Instituto avanzado: generar un XML válido

    Actividad para construir un XML válido a partir de un XSD completo, mezclando restricciones, atributos, expresiones regulares y estructuras anidadas.

    Objetivo

    El esquema del instituto es más exigente que en el ejercicio anterior. El XML deberá respetar atributos obligatorios, valores restringidos, expresiones regulares, elementos repetibles y estructuras internas.

    Lee el XSD con calma antes de escribir el XML. Primero identifica la estructura general y después completa cada parte.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="instituto">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="aulas">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="aula" maxOccurs="unbounded">
                <xs:complexType>
                  <xs:sequence>
                    <xs:element name="nombre" type="xs:string" />
                    <xs:element name="capacidad">
                      <xs:simpleType>
                        <xs:restriction base="xs:integer">
                          <xs:minInclusive value="10" />
                          <xs:maxInclusive value="40" />
                        </xs:restriction>
                      </xs:simpleType>
                    </xs:element>
                    <xs:element name="profesoresAsignados">
                      <xs:complexType>
                        <xs:sequence>
                          <xs:element name="profesorAsignado" minOccurs="1" maxOccurs="unbounded">
                            <xs:complexType>
                              <xs:sequence>
                                <xs:element name="idProfesor">
                                  <xs:simpleType>
                                    <xs:restriction base="xs:positiveInteger" />
                                  </xs:simpleType>
                                </xs:element>
                                <xs:element name="horasSemanales">
                                  <xs:simpleType>
                                    <xs:restriction base="xs:integer">
                                      <xs:minInclusive value="1" />
                                      <xs:maxInclusive value="30" />
                                    </xs:restriction>
                                  </xs:simpleType>
                                </xs:element>
                              </xs:sequence>
                              <xs:attribute name="rol" use="required">
                                <xs:simpleType>
                                  <xs:restriction base="xs:string">
                                    <xs:enumeration value="tutor" />
                                    <xs:enumeration value="docente" />
                                    <xs:enumeration value="apoyo" />
                                  </xs:restriction>
                                </xs:simpleType>
                              </xs:attribute>
                            </xs:complexType>
                          </xs:element>
                        </xs:sequence>
                      </xs:complexType>
                    </xs:element>
                  </xs:sequence>
                  <xs:attribute name="codigo" use="required">
                    <xs:simpleType>
                      <xs:restriction base="xs:string">
                        <xs:pattern value="A[0-9][0-9][0-9]" />
                      </xs:restriction>
                    </xs:simpleType>
                  </xs:attribute>
                  <xs:attribute name="planta" type="xs:integer" use="optional" />
                </xs:complexType>
              </xs:element>
            </xs:sequence>
          </xs:complexType>
        </xs:element>

        <xs:element name="profesores">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="profesor" maxOccurs="unbounded">
                <xs:complexType>
                  <xs:sequence>
                    <xs:element name="nombre" type="xs:string" />
                    <xs:element name="email">
                      <xs:simpleType>
                        <xs:restriction base="xs:string">
                          <xs:pattern value=".+@.+" />
                        </xs:restriction>
                      </xs:simpleType>
                    </xs:element>
                    <xs:element name="departamento" type="xs:string" />
                  </xs:sequence>
                  <xs:attribute name="id" use="required">
                    <xs:simpleType>
                      <xs:restriction base="xs:positiveInteger" />
                    </xs:simpleType>
                  </xs:attribute>
                </xs:complexType>
              </xs:element>
            </xs:sequence>
          </xs:complexType>
        </xs:element>

        <xs:element name="alumnos">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="alumno" maxOccurs="unbounded">
                <xs:complexType>
                  <xs:sequence>
                    <xs:element name="nombre" type="xs:string" />
                    <xs:element name="curso">
                      <xs:simpleType>
                        <xs:restriction base="xs:string">
                          <xs:enumeration value="1DAM" />
                          <xs:enumeration value="1DAW" />
                          <xs:enumeration value="2DAM" />
                          <xs:enumeration value="2DAW" />
                        </xs:restriction>
                      </xs:simpleType>
                    </xs:element>
                    <xs:element name="aulasAsignadas">
                      <xs:complexType>
                        <xs:sequence>
                          <xs:element name="aulaAsignada" minOccurs="1" maxOccurs="unbounded">
                            <xs:complexType>
                              <xs:simpleContent>
                                <xs:extension base="xs:string">
                                  <xs:attribute name="principal" type="xs:boolean" use="optional" />
                                </xs:extension>
                              </xs:simpleContent>
                            </xs:complexType>
                          </xs:element>
                        </xs:sequence>
                      </xs:complexType>
                    </xs:element>
                  </xs:sequence>
                  <xs:attribute name="codigo" use="required">
                    <xs:simpleType>
                      <xs:restriction base="xs:string">
                        <xs:pattern value="ALU-[0-9][0-9][0-9]" />
                      </xs:restriction>
                    </xs:simpleType>
                  </xs:attribute>
                  <xs:attribute name="repetidor" type="xs:boolean" use="optional" />
                </xs:complexType>
              </xs:element>
            </xs:sequence>
          </xs:complexType>
        </xs:element>
      </xs:sequence>

      <xs:attribute name="nombreCentro" type="xs:string" use="required" />
      <xs:attribute name="cursoAcademico" type="xs:string" use="required" />
    </xs:complexType>
  </xs:element>
</xs:schema>

    Pistas para leer el esquema

    • La raíz debe ser <instituto>.
    • <instituto> tiene dos atributos obligatorios: nombreCentro y cursoAcademico.
    • Dentro de <instituto> deben aparecer, en este orden: <aulas>, <profesores> y <alumnos>.
    • Cada profesor tiene un atributo id que debe ser un número entero positivo.
    • Las aulas tienen un atributo codigo con formato A001, A002, etc.
    • Los alumnos tienen un atributo codigo con formato ALU-001, ALU-002, etc.
    • Cada aula debe tener uno o varios profesores asignados.
    • Cada alumno debe tener una o varias aulas asignadas.
    • Los campos curso, rol, capacidad, horasSemanales y email tienen restricciones.

    Tarea

    Genera un XML válido que cumpla el XSD anterior. El XML debe incluir, como mínimo:

    • Dos aulas.
    • Dos profesores.
    • Tres alumnos.
    • Al menos un aula con más de un profesor asignado.
    • Al menos un alumno asignado a más de un aula.
    • Al menos un atributo opcional utilizado, como planta, principal o repetidor.

    Valida el XML con Visual Studio Code y las extensiones instaladas en los ejercicios anteriores.

    Pruebas de error

    Cuando tengas un XML válido, provoca algunos errores para comprobar que entiendes las reglas:

    • Usa un código de aula como 101 en lugar de A101.
    • Usa un código de alumno como ALUMNO-001 en lugar de ALU-001.
    • Escribe una capacidad menor que 10 o mayor que 40.
    • Utiliza un rol de profesor asignado que no sea tutor, docente o apoyo.
    • Quita todos los profesores asignados de un aula.
    • Escribe un email sin @.
    • Cambia el orden de <aulas>, <profesores> y <alumnos>.

    2.8 Canciones: definir y reutilizar tipos simples

    Actividad para practicar la creación de tipos simples propios y reutilizarlos en varios elementos.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:simpleType name="tipoDuracion">
    <xs:restriction base="xs:integer">
      <xs:minInclusive value="1" />
      <xs:maxInclusive value="600" />
    </xs:restriction>
  </xs:simpleType>

  <xs:simpleType name="tipoGeneroMusical">
    <xs:restriction base="xs:string">
      <xs:enumeration value="rock" />
      <xs:enumeration value="pop" />
      <xs:enumeration value="jazz" />
      <xs:enumeration value="electronica" />
    </xs:restriction>
  </xs:simpleType>

  <xs:element name="cancion">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="titulo" type="xs:string" />
        <xs:element name="genero" type="tipoGeneroMusical" />
        <xs:element name="duracionSegundos" type="tipoDuracion" />
      </xs:sequence>
    </xs:complexType>
  </xs:element>
</xs:schema>

    Tarea

    Genera un XML válido. Después comprueba qué ocurre si la duración es 0, 800 o si el género no está en la lista.

    2.9 Recetas: tipos complejos que usan otros tipos

    Actividad para practicar un tipo complejo reutilizable que emplea tipos simples inventados previamente.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:simpleType name="tipoCantidad">
    <xs:restriction base="xs:decimal">
      <xs:minExclusive value="0" />
    </xs:restriction>
  </xs:simpleType>

  <xs:simpleType name="tipoUnidad">
    <xs:restriction base="xs:string">
      <xs:enumeration value="g" />
      <xs:enumeration value="ml" />
      <xs:enumeration value="unidad" />
    </xs:restriction>
  </xs:simpleType>

  <xs:complexType name="tipoIngrediente">
    <xs:sequence>
      <xs:element name="nombre" type="xs:string" />
      <xs:element name="cantidad" type="tipoCantidad" />
      <xs:element name="unidad" type="tipoUnidad" />
    </xs:sequence>
    <xs:attribute name="opcional" type="xs:boolean" use="optional" />
  </xs:complexType>

  <xs:element name="receta">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="nombre" type="xs:string" />
        <xs:element name="ingrediente" type="tipoIngrediente" minOccurs="1" maxOccurs="unbounded" />
      </xs:sequence>
    </xs:complexType>
  </xs:element>
</xs:schema>

    Tarea

    Genera un XML válido con una receta y al menos tres ingredientes. Usa el atributo opcional opcional en uno de ellos.

    2.10 Instituto avanzado con tipos reutilizables

    Actividad para construir un XML válido a partir de un XSD más completo, mezclando restricciones, atributos, tipos propios y estructuras anidadas.

    Objetivo

    Partimos de la idea del ejercicio anterior, pero ahora el esquema del instituto es más exigente. El XML deberá respetar tipos personalizados, atributos obligatorios, valores restringidos, expresiones regulares y elementos repetibles.

    Lee el XSD con calma antes de escribir el XML. No intentes rellenar datos al azar: primero identifica la estructura general y después completa cada parte.

    XSD de partida

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:simpleType name="tipoIdPositivo">
    <xs:restriction base="xs:positiveInteger" />
  </xs:simpleType>

  <xs:simpleType name="tipoCodigoAula">
    <xs:restriction base="xs:string">
      <xs:pattern value="A[0-9][0-9][0-9]" />
    </xs:restriction>
  </xs:simpleType>

  <xs:simpleType name="tipoCodigoAlumno">
    <xs:restriction base="xs:string">
      <xs:pattern value="ALU-[0-9][0-9][0-9]" />
    </xs:restriction>
  </xs:simpleType>

  <xs:simpleType name="tipoCurso">
    <xs:restriction base="xs:string">
      <xs:enumeration value="1DAM" />
      <xs:enumeration value="1DAW" />
      <xs:enumeration value="2DAM" />
      <xs:enumeration value="2DAW" />
    </xs:restriction>
  </xs:simpleType>

  <xs:simpleType name="tipoEmail">
    <xs:restriction base="xs:string">
      <xs:pattern value=".+@.+" />
    </xs:restriction>
  </xs:simpleType>

  <xs:simpleType name="tipoHoras">
    <xs:restriction base="xs:integer">
      <xs:minInclusive value="1" />
      <xs:maxInclusive value="30" />
    </xs:restriction>
  </xs:simpleType>

  <xs:complexType name="tipoProfesorAsignado">
    <xs:sequence>
      <xs:element name="idProfesor" type="tipoIdPositivo" />
      <xs:element name="horasSemanales" type="tipoHoras" />
    </xs:sequence>
    <xs:attribute name="rol" use="required">
      <xs:simpleType>
        <xs:restriction base="xs:string">
          <xs:enumeration value="tutor" />
          <xs:enumeration value="docente" />
          <xs:enumeration value="apoyo" />
        </xs:restriction>
      </xs:simpleType>
    </xs:attribute>
  </xs:complexType>

  <xs:complexType name="tipoAulaAsignada">
    <xs:simpleContent>
      <xs:extension base="tipoCodigoAula">
        <xs:attribute name="principal" type="xs:boolean" use="optional" />
      </xs:extension>
    </xs:simpleContent>
  </xs:complexType>

  <xs:element name="instituto">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="aulas">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="aula" maxOccurs="unbounded">
                <xs:complexType>
                  <xs:sequence>
                    <xs:element name="nombre" type="xs:string" />
                    <xs:element name="capacidad">
                      <xs:simpleType>
                        <xs:restriction base="xs:integer">
                          <xs:minInclusive value="10" />
                          <xs:maxInclusive value="40" />
                        </xs:restriction>
                      </xs:simpleType>
                    </xs:element>
                    <xs:element name="profesoresAsignados">
                      <xs:complexType>
                        <xs:sequence>

                      </xs:complexType>
                    </xs:element>
                  </xs:sequence>
                  <xs:attribute name="codigo" type="tipoCodigoAula" use="required" />
                  <xs:attribute name="planta" type="xs:integer" use="optional" />
                </xs:complexType>
              </xs:element>
            </xs:sequence>
          </xs:complexType>
        </xs:element>

        <xs:element name="profesores">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="profesor" maxOccurs="unbounded">
                <xs:complexType>
                  <xs:sequence>
                    <xs:element name="nombre" type="xs:string" />
                    <xs:element name="email" type="tipoEmail" />
                    <xs:element name="departamento" type="xs:string" />
                  </xs:sequence>
                  <xs:attribute name="id" type="tipoIdPositivo" use="required" />
                </xs:complexType>
              </xs:element>
            </xs:sequence>
          </xs:complexType>
        </xs:element>

        <xs:element name="alumnos">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="alumno" maxOccurs="unbounded">
                <xs:complexType>
                  <xs:sequence>
                    <xs:element name="nombre" type="xs:string" />
                    <xs:element name="curso" type="tipoCurso" />
                    <xs:element name="aulasAsignadas">
                      <xs:complexType>
                        <xs:sequence>
                          <xs:element name="aulaAsignada" type="tipoAulaAsignada" minOccurs="1" maxOccurs="unbounded" />
                        </xs:sequence>
                      </xs:complexType>
                    </xs:element>
                  </xs:sequence>
                  <xs:attribute name="codigo" type="tipoCodigoAlumno" use="required" />
                  <xs:attribute name="repetidor" type="xs:boolean" use="optional" />
                </xs:complexType>
              </xs:element>
            </xs:sequence>
          </xs:complexType>
        </xs:element>
      </xs:sequence>

      <xs:attribute name="nombreCentro" type="xs:string" use="required" />
      <xs:attribute name="cursoAcademico" type="xs:string" use="required" />
    </xs:complexType>
  </xs:element>
</xs:schema>

    Pistas para leer el esquema

    • La raíz debe ser <instituto>.
    • <instituto> tiene dos atributos obligatorios: nombreCentro y cursoAcademico.
    • Dentro de <instituto> deben aparecer, en este orden: <aulas>, <profesores> y <alumnos>.
    • Cada profesor tiene un atributo id que debe ser un número entero positivo.
    • Las aulas tienen un atributo codigo con formato A001, A002, etc.
    • Los alumnos tienen un atributo codigo con formato ALU-001, ALU-002, etc.
    • Cada aula debe tener uno o varios profesores asignados.
    • Cada alumno debe tener una o varias aulas asignadas.
    • Los campos curso, rol, capacidad, horasSemanales y email tienen restricciones.

    Tarea

    Genera un XML válido que cumpla el XSD anterior. El XML debe incluir, como mínimo:

    • Dos aulas.
    • Dos profesores.
    • Tres alumnos.
    • Al menos un aula con más de un profesor asignado.
    • Al menos un alumno asignado a más de un aula.
    • Al menos un atributo opcional utilizado, como planta, principal o repetidor.

    Valida el XML con Visual Studio Code y las extensiones instaladas en el ejercicio anterior.

    Pruebas de error

    Cuando tengas un XML válido, provoca algunos errores para comprobar que entiendes las reglas:

    • Usa un código de aula como 101 en lugar de A101.
    • Usa un código de alumno como ALUMNO-001 en lugar de ALU-001.
    • Escribe una capacidad menor que 10 o mayor que 40.
    • Utiliza un rol de profesor asignado que no sea tutor, docente o apoyo.
    • Quita todos los profesores asignados de un aula.
    • Escribe un email sin @.
    • Cambia el orden de <aulas>, <profesores> y <alumnos>.

    2.11 Soluciones orientativas

    Ejemplos de XML válidos para los ejercicios propuestos. No son la única solución posible, pero sirven como referencia para comprobar la estructura.

    Consulta estas soluciones después de haber intentado crear tus propios XML y validarlos con el XSD correspondiente.
    En los ejemplos se da por hecho que el archivo XML y su archivo XSD están guardados en la misma carpeta. Por eso se utiliza directamente el nombre del XSD en xsi:noNamespaceSchemaLocation.
