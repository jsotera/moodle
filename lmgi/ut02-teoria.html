    2.1 ¿Qué es XSD?

    XSD permite definir qué estructura, elementos, atributos y tipos de datos debe cumplir un documento XML para considerarse válido.

    Además de esta documentación de clase, puedes consultar la documentación completa sobre XSD en W3Schools XML Schema Tutorial.

    Idea principal

    XSD significa XML Schema Definition. Un XSD es un documento que describe las reglas que debe cumplir otro documento XML.

    En la UT1 vimos que un XML puede estar bien formado: etiquetas cerradas, anidadas correctamente, un único elemento raíz, atributos entre comillas, etc. Pero eso no garantiza que el documento tenga los datos correctos.

    <alumno>
  <nombre>Ane</nombre>
  <edad>diecisiete</edad>
</alumno>

    Este XML puede estar bien formado, pero quizá para nuestra aplicación la edad debe ser un número entero. XSD sirve precisamente para definir ese tipo de reglas.

    Bien formado no es lo mismo que válido

    Concepto Qué comprueba Ejemplo
    XML bien formado Que la sintaxis XML es correcta. Las etiquetas se abren y cierran bien.
    XML válido Que el XML cumple las reglas de un esquema. <edad> debe contener un número entero.

    Enfoque de esta unidad

    En esta unidad trabajaremos con XSD. Los DTD pueden aparecer como referencia o venir dados, pero el trabajo principal será crear, leer y modificar documentos XML en función de esquemas XSD.

    La pregunta habitual será: ¿este XML cumple el XSD? Si no lo cumple, tendremos que detectar por qué y corregir el XML o el esquema según el caso.

    2.2 Estructura básica de un XSD

    Un XSD también es un documento XML, pero utiliza etiquetas propias del vocabulario XML Schema.

    La etiqueta raíz <xs:schema>

    Todo esquema XSD suele comenzar con la etiqueta <xs:schema>. El prefijo xs indica que estamos usando elementos del lenguaje XML Schema.

    <?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">

  <!-- Aquí se definen las reglas del XML -->

</xs:schema>

    La parte xmlns:xs="http://www.w3.org/2001/XMLSchema" declara el espacio de nombres de XSD. Gracias a ello, etiquetas como <xs:element> o <xs:complexType> tienen significado para un validador.

    Ejemplo mínimo

    Este XSD define que el XML debe tener un elemento llamado <mensaje> cuyo contenido será texto:

    <xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="mensaje" type="xs:string" />
</xs:schema>

    Con ese esquema, este XML sería válido:

    <mensaje>Hola XML</mensaje>

    Pero este otro no cumpliría la regla, porque la raíz no se llama <mensaje>:

    <texto>Hola XML</texto>

    Relación entre XML y XSD

    Un XML puede indicar qué esquema XSD debe usarse para validarlo. Para ello se suelen usar atributos relacionados con xsi y schemaLocation.

    <alumno
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:noNamespaceSchemaLocation="alumno.xsd">
  <nombre>Ane</nombre>
  <edad>17</edad>
</alumno>

    En clase será habitual trabajar con dos ficheros: un XML con datos y un XSD con las reglas que debe cumplir.

    2.3 Elementos simples, tipos de datos y atributos

    XSD permite indicar qué elementos existen, qué tipo de dato contienen y qué atributos pueden usar.

    Elementos simples

    Un elemento simple contiene texto, pero no contiene otros elementos ni atributos propios.

    <nombre>Ane</nombre>
<edad>17</edad>
<fechaNacimiento>2009-04-18</fechaNacimiento>

    En XSD se pueden definir así:

    <xs:element name="nombre" type="xs:string" />
<xs:element name="edad" type="xs:integer" />
<xs:element name="fechaNacimiento" type="xs:date" />

    Tipos de datos habituales

    Tipo XSD Qué representa Ejemplo válido
    xs:string Texto Ane
    xs:integer Número entero 17
    xs:decimal Número con decimales 8.75
    xs:boolean Verdadero o falso true, false, 1, 0
    xs:date Fecha 2026-09-24

    Atributos

    Los atributos también pueden declararse en XSD. Normalmente se definen dentro de un tipo complejo, porque pertenecen a un elemento.

    <alumno id="A001">
  <nombre>Ane</nombre>
</alumno>
    <xs:attribute name="id" type="xs:string" use="required" />

    El atributo use="required" indica que ese atributo es obligatorio. Si no aparece en el XML, el documento no será válido respecto al XSD.

    2.4 Tipos complejos y secuencias

    Los tipos complejos permiten definir elementos que contienen otros elementos, atributos o ambas cosas.

    Elementos con otros elementos dentro

    Muchos documentos XML tienen elementos que agrupan información. Por ejemplo, un elemento <alumno> puede contener <nombre>, <edad> y <curso>.

    <alumno>
  <nombre>Ane</nombre>
  <edad>17</edad>
  <curso>1 DAM</curso>
</alumno>

    En XSD, ese elemento se define con <xs:complexType>:

    <xs:element name="alumno">
  <xs:complexType>
    <xs:sequence>
      <xs:element name="nombre" type="xs:string" />
      <xs:element name="edad" type="xs:integer" />
      <xs:element name="curso" type="xs:string" />
    </xs:sequence>
  </xs:complexType>
</xs:element>

    La importancia del orden

    <xs:sequence> indica que los elementos hijos deben aparecer en el mismo orden en el que se han declarado.

    XML Resultado Motivo
    <nombre>, <edad>, <curso> Válido Respeta el orden del XSD.
    <edad>, <nombre>, <curso> No válido No respeta la secuencia definida.

    Repeticiones y obligatoriedad

    Con minOccurs y maxOccurs podemos indicar cuántas veces puede aparecer un elemento.

    <xs:element name="telefono" type="xs:string" minOccurs="0" maxOccurs="unbounded" />

    Este ejemplo indica que <telefono> puede no aparecer, aparecer una vez o aparecer muchas veces.

    2.5 Restricciones y validación

    Las restricciones permiten limitar los valores aceptados por un elemento o atributo.

    Restricciones numéricas

    Podemos indicar valores mínimos y máximos. Por ejemplo, una edad entre 0 y 120:

    <xs:element name="edad">
  <xs:simpleType>
    <xs:restriction base="xs:integer">
      <xs:minInclusive value="0" />
      <xs:maxInclusive value="120" />
    </xs:restriction>
  </xs:simpleType>
</xs:element>

    <edad>17</edad> sería válido, pero <edad>200</edad> no lo sería.

    Valores permitidos

    Con <xs:enumeration> podemos limitar un valor a una lista cerrada de opciones.

    <xs:element name="modalidad">
  <xs:simpleType>
    <xs:restriction base="xs:string">
      <xs:enumeration value="DAM" />
      <xs:enumeration value="DAW" />
      <xs:enumeration value="ASIR" />
    </xs:restriction>
  </xs:simpleType>
</xs:element>

    En este caso, <modalidad>DAM</modalidad> sería válido, pero <modalidad>Bachillerato</modalidad> no.

    Patrones

    Con <xs:pattern> podemos obligar a que un texto siga una forma concreta. Por ejemplo, un código de alumno formado por la letra A y tres dígitos:

    <xs:element name="codigo">
  <xs:simpleType>
    <xs:restriction base="xs:string">
      <xs:pattern value="A[0-9][0-9][0-9]" />
    </xs:restriction>
  </xs:simpleType>
</xs:element>

    <codigo>A125</codigo> sería válido, pero <codigo>AL125</codigo> no.

    Cómo pensaremos la validación

    Para validar un XML frente a un XSD seguiremos siempre una idea sencilla:

    • Leer el XSD para localizar la raíz esperada.
    • Comprobar qué elementos y atributos son obligatorios.
    • Revisar el orden definido por las secuencias.
    • Comprobar los tipos de datos.
    • Aplicar restricciones: rangos, enumeraciones, patrones y repeticiones.

    Durante la unidad trabajaremos mucho modificando XML para que cumplan un XSD dado, y también modificando XSD para expresar nuevas reglas.
