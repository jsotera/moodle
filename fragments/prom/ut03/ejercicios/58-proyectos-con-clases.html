Nueva tanda: proyectos con clases y métodos

Tras las actividades JavaFX, continúa con los proyectos 3.46–3.48: trabajarás en clases de modelo y en el método main, con los atributos, constructores y firmas de los métodos ya preparados.

TODOs ordenados por clase

Cada tarea está señalada mediante un comentario numerado. Completa primero la interfaz de consola, después las clases de modelo y, al final, el programa que las utiliza:

  • Clase GUI: TODO 01, TODO 02…
  • Primera clase de modelo: TODO 11, TODO 12…
  • Segunda clase de modelo: TODO 21, TODO 22…
  • Clase Main: TODO 31, TODO 32…

Cada TODO aparece como un punto individual en el enunciado de su ejercicio, con el mismo número y exactamente el mismo texto que en el código. Las aclaraciones se encuentran debajo de ese punto. El comentario indica el resultado que se pide, sin pseudocódigo ni instrucciones de implementación.

Los métodos están documentados con Javadoc: lee qué reciben, qué devuelven y qué deben hacer cuando una operación no es válida. Conserva los nombres, parámetros y tipos de retorno. No necesitas añadir clases ni métodos auxiliares; tampoco arrays ni colecciones.

Código proporcionado y tareas pendientes

Los getters y setters que solo acceden directamente a un atributo, los constructores de asignación directa y los toString de descripción directa se proporcionan implementados cuando existen. No son tareas del ejercicio.

Solo los cuerpos pendientes llevan retornos provisionales: return 0; para enteros, return false; para booleanos y return null; para objetos o textos. Los constructores pendientes y métodos void pendientes contienen únicamente sus TODOs.

Esos valores permiten compilar, pero no son la solución ni necesariamente el resultado correcto. Sustitúyelos al implementar cada operación pendiente. Un proyecto recién descargado ejecuta un main vacío y termina sin mostrar nada.

No cambies un retorno para superar una prueba aislada: implementa el comportamiento completo y comprueba también los casos rechazados, las referencias compartidas y los límites.

Abrir y ejecutar

Descomprime cada ZIP en su propia carpeta y abre su pom.xml con IntelliJ IDEA. Configura JDK 25, también para el importador y el ejecutor Maven, y espera a que se cargue el proyecto. Los proyectos compilan para Java 25, sin características preview. Ejecuta edu.masanz.da.ut3.app.Main con el triángulo verde junto a main; utiliza Debug para seguir los cambios de estado.

Las clases de modelo están en edu.masanz.da.ut3.modelo, la clase principal en edu.masanz.da.ut3.app y la interfaz de consola en edu.masanz.da.ut3.gui.GUI. Los proyectos son independientes, aunque compartan estos nombres de paquete. Las descargas contienen únicamente la base, sin soluciones.

Interfaz de consola

La clase GUI contiene métodos sencillos para imprimir mensajes y TODOs para solicitar datos, como pedirOpcion(). Main coordina sus llamadas con las operaciones del modelo; las clases de modelo no leen del teclado ni imprimen.

Todos los métodos de GUI son estáticos: se invocan mediante GUI.mostrarMenu() o GUI.pedirOpcion(), sin crear instancias. La lectura utiliza un único atributo private static Scanner scanner = new Scanner(System.in);.

GUI no conoce las clases del modelo: recibe textos y valores sencillos. Main consulta los objetos, toma las decisiones y pasa a la interfaz únicamente los datos que debe mostrar.

Las opciones de los menús aparecen en orden: 1, 2, 3… y, al final, 0 para salir. Cada enunciado incluye los métodos de GUI y ejemplos de las pantallas esperadas al completar los TODOs.
