2.6 Consolas prestadas y referencias

Trabaja con tres modelos relacionados entre sí: Persona, Consola y VideoJuego.

Proyecto base

Descarga el proyecto Maven base y ábrelo con IntelliJ IDEA. El proyecto contiene las clases Persona, Consola y VideoJuego documentadas con Javadoc, además de una clase Main preparada para completar la actividad.

Descargar proyecto base

Objetivo

El objetivo es observar cómo varios objetos pueden quedar conectados entre sí mediante referencias: una persona usa una consola, la consola tiene un propietario fijo y la consola ejecuta un videojuego concreto.

No debes modificar las clases del paquete modelo. Toda la lógica de prueba debe escribirse en el método main.

Reglas del modelo

  • Una Persona tiene nombre, estado y una consolaEnUso.
  • Una Consola tiene un propietario fijo, un modelo, un estado operativo y un videojuego insertado.
  • El propietario de una consola no cambia aunque la consola se preste a otra persona.
  • Una consola solo puede utilizarse a través de métodos de una Persona.
  • Para utilizar una consola, primero debe tener un videojuego insertado.
  • Cada vez que se usa un juego, aumenta su contador de usos.
  • Cada uso tiene un 50% de probabilidad de estropear la consola.
  • Si un mismo videojuego se utiliza más de 3 veces, la consola se estropea automáticamente.
  • Cuando una consola se estropea, su propietario pasa a tener el estado enfadado.

Enunciado

Crea una aplicación de prueba con las siguientes condiciones:

  • Crea al menos 3 personas.
  • Crea una consola cuyo propietario sea una de esas personas.
  • Crea al menos 2 videojuegos.
  • Haz que el propietario reciba su consola, inserte un videojuego y la utilice.
  • Presta la consola a otra persona y vuelve a utilizarla desde esa persona.
  • Comprueba que la consola sigue perteneciendo a la persona propietaria original.
  • Utiliza varias veces el mismo videojuego hasta provocar que la consola se estropee.
  • Consulta el estado de la persona propietaria desde su variable original del Main.

La trampa importante

La persona que usa la consola no tiene por qué ser su propietaria. Si la consola se rompe mientras la está usando otra persona, quien se enfada es la persona propietaria original.

Ese cambio se verá también si consultas el objeto Persona original que creaste en Main, porque es la misma referencia que guarda la consola como propietaria.

Pruebas avanzadas

  • Intenta utilizar una consola sin haber insertado ningún videojuego.
  • Inserta un videojuego, presta la consola y comprueba que el videojuego insertado sigue dentro.
  • Usa el mismo videojuego desde distintas personas y observa que su contador de usos sigue aumentando.
  • Crea una segunda consola y compara qué propietario se enfada cuando se estropea cada una.

Salida esperada

La salida puede variar porque existe probabilidad de avería, pero debería mostrar mensajes similares a estos:

Ane tiene ahora en uso la consola RetroBox.
Se ha insertado Pixel Kart en RetroBox.
Ejecutando Pixel Kart en RetroBox. Uso numero 1.
Ane ha prestado la consola a Markel.
Ejecutando Pixel Kart en RetroBox. Uso numero 2.
La consola se ha roto por mala suerte.
La consola RetroBox se ha estropeado.
Ane se ha enfadado.
Ane esta enfadado.

Pistas

  • Lee el Javadoc antes de utilizar cada método.
  • Utiliza toString para observar el estado de personas, consolas y videojuegos.
  • No confundas propietario con consolaEnUso.
  • Si la consola se rompe demasiado pronto por probabilidad, vuelve a ejecutar el programa.
