2.5 Restricciones y validación

Las restricciones permiten limitar los valores aceptados por un elemento o atributo.

Restricciones numéricas

Podemos indicar valores mínimos y máximos. Por ejemplo, una edad entre 0 y 120:

<xs:element name="edad">
  <xs:simpleType>
    <xs:restriction base="xs:integer">
      <xs:minInclusive value="0" />
      <xs:maxInclusive value="120" />
    </xs:restriction>
  </xs:simpleType>
</xs:element>

<edad>17</edad> sería válido, pero <edad>200</edad> no lo sería.

Valores permitidos

Con <xs:enumeration> podemos limitar un valor a una lista cerrada de opciones.

<xs:element name="modalidad">
  <xs:simpleType>
    <xs:restriction base="xs:string">
      <xs:enumeration value="DAM" />
      <xs:enumeration value="DAW" />
      <xs:enumeration value="ASIR" />
    </xs:restriction>
  </xs:simpleType>
</xs:element>

En este caso, <modalidad>DAM</modalidad> sería válido, pero <modalidad>Bachillerato</modalidad> no.

Patrones

Con <xs:pattern> podemos obligar a que un texto siga una forma concreta. Por ejemplo, un código de alumno formado por la letra A y tres dígitos:

<xs:element name="codigo">
  <xs:simpleType>
    <xs:restriction base="xs:string">
      <xs:pattern value="A[0-9][0-9][0-9]" />
    </xs:restriction>
  </xs:simpleType>
</xs:element>

<codigo>A125</codigo> sería válido, pero <codigo>AL125</codigo> no.

Cómo pensaremos la validación

Para validar un XML frente a un XSD seguiremos siempre una idea sencilla:

  • Leer el XSD para localizar la raíz esperada.
  • Comprobar qué elementos y atributos son obligatorios.
  • Revisar el orden definido por las secuencias.
  • Comprobar los tipos de datos.
  • Aplicar restricciones: rangos, enumeraciones, patrones y repeticiones.

Durante la unidad trabajaremos mucho modificando XML para que cumplan un XSD dado, y también modificando XSD para expresar nuevas reglas.
