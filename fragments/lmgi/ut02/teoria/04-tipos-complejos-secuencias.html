2.4 Tipos complejos y secuencias

Los tipos complejos permiten definir elementos que contienen otros elementos, atributos o ambas cosas.

Elementos con otros elementos dentro

Muchos documentos XML tienen elementos que agrupan información. Por ejemplo, un elemento <alumno> puede contener <nombre>, <edad> y <curso>.

<alumno>
  <nombre>Ane</nombre>
  <edad>17</edad>
  <curso>1 DAM</curso>
</alumno>

En XSD, ese elemento se define con <xs:complexType>:

<xs:element name="alumno">
  <xs:complexType>
    <xs:sequence>
      <xs:element name="nombre" type="xs:string" />
      <xs:element name="edad" type="xs:integer" />
      <xs:element name="curso" type="xs:string" />
    </xs:sequence>
  </xs:complexType>
</xs:element>

La importancia del orden

<xs:sequence> indica que los elementos hijos deben aparecer en el mismo orden en el que se han declarado.

XML Resultado Motivo
<nombre>, <edad>, <curso> Válido Respeta el orden del XSD.
<edad>, <nombre>, <curso> No válido No respeta la secuencia definida.

Repeticiones y obligatoriedad

Con minOccurs y maxOccurs podemos indicar cuántas veces puede aparecer un elemento.

<xs:element name="telefono" type="xs:string" minOccurs="0" maxOccurs="unbounded" />

Este ejemplo indica que <telefono> puede no aparecer, aparecer una vez o aparecer muchas veces.
