2.6 Ejemplos completos: mezclando reglas XSD

En un XSD real es habitual mezclar elementos simples, restricciones, atributos, tipos complejos y elementos anidados.

Por qué necesitamos ejemplos completos

Hasta ahora hemos visto las piezas por separado: elementos, atributos, secuencias, tipos de datos y restricciones. En la práctica, un esquema XSD suele combinar varias de estas piezas al mismo tiempo.

La idea es leer el XSD como si fuera un contrato: indica qué etiquetas puede tener el XML, en qué orden, con qué atributos y qué valores se consideran válidos.

Ejemplo 1: alumno con restricciones y atributos

Este XML representa un alumno. Tiene un atributo obligatorio id, elementos simples y varios valores restringidos.

<alumno id="A125">
  <nombre>Nerea</nombre>
  <edad>17</edad>
  <modalidad>DAM</modalidad>
  <notaMedia>8.4</notaMedia>
</alumno>

Un posible XSD para validarlo sería:

<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="alumno">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="nombre" type="xs:string" />

        <xs:element name="edad">
          <xs:simpleType>
            <xs:restriction base="xs:integer">
              <xs:minInclusive value="16" />
              <xs:maxInclusive value="65" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>

        <xs:element name="modalidad">
          <xs:simpleType>
            <xs:restriction base="xs:string">
              <xs:enumeration value="DAM" />
              <xs:enumeration value="DAW" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>

        <xs:element name="notaMedia">
          <xs:simpleType>
            <xs:restriction base="xs:decimal">
              <xs:minInclusive value="0" />
              <xs:maxInclusive value="10" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>
      </xs:sequence>

      <xs:attribute name="id" use="required">
        <xs:simpleType>
          <xs:restriction base="xs:string">
            <xs:pattern value="A[0-9][0-9][0-9]" />
          </xs:restriction>
        </xs:simpleType>
      </xs:attribute>
    </xs:complexType>
  </xs:element>
</xs:schema>

En este ejemplo se mezclan varias reglas: el atributo id es obligatorio, la edad tiene rango, la modalidad tiene valores permitidos y la nota media debe estar entre 0 y 10.

Ejemplo 2: tipo complejo dentro de otro tipo complejo

Un tipo complejo puede contener otro elemento que, a su vez, también tenga estructura interna. Por ejemplo, una matrícula contiene los datos de un alumno y los datos de un módulo.

<matricula curso="2026-2027">
  <alumno>
    <nombre>Iker</nombre>
    <email>iker@example.com</email>
  </alumno>
  <modulo codigo="LMSGI">
    <nombre>Lenguaje de Marcas</nombre>
    <horas>128</horas>
  </modulo>
</matricula>

El XSD puede definir una estructura anidada:

<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="matricula">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="alumno">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="nombre" type="xs:string" />
              <xs:element name="email">
                <xs:simpleType>
                  <xs:restriction base="xs:string">
                    <xs:pattern value=".+@.+" />
                  </xs:restriction>
                </xs:simpleType>
              </xs:element>
            </xs:sequence>
          </xs:complexType>
        </xs:element>

        <xs:element name="modulo">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="nombre" type="xs:string" />
              <xs:element name="horas">
                <xs:simpleType>
                  <xs:restriction base="xs:integer">
                    <xs:minInclusive value="1" />
                  </xs:restriction>
                </xs:simpleType>
              </xs:element>
            </xs:sequence>
            <xs:attribute name="codigo" type="xs:string" use="required" />
          </xs:complexType>
        </xs:element>
      </xs:sequence>

      <xs:attribute name="curso" type="xs:string" use="required" />
    </xs:complexType>
  </xs:element>
</xs:schema>

Aquí aparecen dos niveles de estructura: <matricula> contiene <alumno> y <modulo>, y ambos tienen sus propios elementos internos.

Ejemplo 3: contenido simple con atributo

A veces un elemento no tiene hijos, solo texto, pero además necesita atributos. Por ejemplo, una nota puede tener como contenido el valor numérico y como atributo la convocatoria.

<nota convocatoria="ordinaria">8.5</nota>

Este caso tiene un poco más de miga: no basta con declarar un <xs:simpleType>, porque los tipos simples no pueden tener atributos. Para tener texto y atributos a la vez necesitamos un <xs:complexType> con <xs:simpleContent>.

<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="nota">
    <xs:complexType>
      <xs:simpleContent>
        <xs:extension base="tipoNota">
          <xs:attribute name="convocatoria" use="required">
            <xs:simpleType>
              <xs:restriction base="xs:string">
                <xs:enumeration value="ordinaria" />
                <xs:enumeration value="extraordinaria" />
              </xs:restriction>
            </xs:simpleType>
          </xs:attribute>
        </xs:extension>
      </xs:simpleContent>
    </xs:complexType>
  </xs:element>

  <xs:simpleType name="tipoNota">
    <xs:restriction base="xs:decimal">
      <xs:minInclusive value="0" />
      <xs:maxInclusive value="10" />
    </xs:restriction>
  </xs:simpleType>
</xs:schema>

En este ejemplo, el contenido de <nota> debe cumplir el tipo tipoNota, pero además el elemento debe tener un atributo convocatoria con uno de los valores permitidos.

XML Resultado Motivo
<nota convocatoria="ordinaria">8.5</nota> Válido La nota está entre 0 y 10, y la convocatoria está permitida.
<nota convocatoria="final">8.5</nota> No válido final no aparece en la enumeración.
<nota convocatoria="ordinaria">12</nota> No válido El contenido no respeta el rango definido en tipoNota.

Cómo leer estos ejemplos

  • Primero localiza el elemento raíz del XML.
  • Después busca en el XSD el <xs:element> con ese nombre.
  • Si tiene <xs:complexType>, revisa qué elementos hijos permite.
  • Si aparece <xs:sequence>, respeta el orden indicado.
  • Comprueba atributos obligatorios con use="required".
  • Por último, revisa restricciones como rangos, enumeraciones o patrones.
