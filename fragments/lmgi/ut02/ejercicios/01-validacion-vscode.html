2.1 Validar XML con XSD en Visual Studio Code

Actividad para comprobar cómo un editor puede ayudarnos a detectar errores de validación cuando un XML está asociado a un esquema XSD.

Punto de partida

Vamos a utilizar el ejemplo completo de XML y XSD que aparece en W3Schools:

W3Schools - XML Schema Example

En esa página se trabaja con un pedido llamado shiporder. El XML contiene datos como la persona que realiza el pedido, la dirección de envío y varios productos. El XSD define qué estructura debe cumplir ese XML.

Preparar los archivos

  1. Crea una carpeta para la actividad.
  2. Dentro de esa carpeta, crea un archivo llamado shiporder.xml.
  3. Copia en ese archivo el XML de ejemplo que aparece en W3Schools.
  4. Crea otro archivo llamado shiporder.xsd.
  5. Copia en ese archivo el XSD de ejemplo de la misma página.

Es importante que ambos archivos estén en la misma carpeta, porque el XML indica que su esquema se encuentra en shiporder.xsd.

carpeta-actividad/
  shiporder.xml
  shiporder.xsd

Relación entre XML y XSD

Fíjate en que el XML contiene una referencia al esquema XSD:

<shiporder orderid="889923"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:noNamespaceSchemaLocation="shiporder.xsd">

La parte xsi:noNamespaceSchemaLocation="shiporder.xsd" indica al editor y a las herramientas de validación qué archivo XSD deben utilizar para comprobar el XML.

Instalar extensiones en Visual Studio Code

Abre Visual Studio Code y entra en la sección de extensiones. Instala estas extensiones:

  • XML, de Red Hat.
  • XML Tools.

Después, abre la carpeta completa de la actividad desde Visual Studio Code. No abras solo el archivo suelto: abre la carpeta para que el editor pueda encontrar correctamente el XML y el XSD.

Comprobar que todo funciona

Si todo está bien configurado, Visual Studio Code debería mostrar el XML correctamente y no debería marcar errores de validación.

Comprueba también que puedes navegar cómodamente por el XML, ver las etiquetas coloreadas y detectar la estructura del documento.

Provocar errores de validación

Ahora modifica el XML para comprobar si el IDE detecta los errores. Prueba, por ejemplo:

  • Cambiar el nombre de una etiqueta, por ejemplo <orderperson> por <persona>.
  • Eliminar un elemento obligatorio.
  • Cambiar el orden de los elementos dentro de <shiporder>.
  • Quitar el atributo orderid.
  • Escribir texto donde el XSD espera un número, por ejemplo en <quantity> o <price>.
  • Cambiar el nombre del archivo XSD o modificar la ruta de xsi:noNamespaceSchemaLocation.

Observa qué errores aparecen, dónde los marca Visual Studio Code y qué información ofrece para ayudarte a corregirlos.

Volver a dejarlo válido

Después de probar errores, corrige el XML hasta que vuelva a ser válido. La actividad termina cuando seas capaz de:

  • Explicar qué archivo contiene los datos.
  • Explicar qué archivo contiene las reglas.
  • Identificar cómo se enlaza el XML con el XSD.
  • Provocar al menos tres errores distintos.
  • Corregir esos errores hasta que el editor deje de marcarlos.
