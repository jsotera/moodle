    3.1 Comparación de números

    Practica if, else if y else comparando dos números enteros.

    Cómo trabajaremos en estas actividades

    Crea un proyecto con una clase Main y su método public static void main(String[] args). Escribe toda la lógica dentro de main, utilizando variables locales, expresiones, condicionales y, cuando se soliciten, bucles. No declares atributos, constructores, métodos auxiliares ni clases de modelo. Tampoco necesitas arrays ni colecciones.

    Puedes utilizar clases de Java como Scanner, Random y Math. Los import necesarios se escriben antes de la declaración de Main. Estas normas se aplican a toda la tanda de ejercicios.

    En los primeros ejercicios puedes asignar los datos directamente a las variables y cambiarlos entre ejecuciones. Cuando se pida entrada por teclado, utiliza Scanner. Este ejemplo solo muestra cómo leer un entero:

    import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);
        System.out.print("Introduce un número entero: ");
        int numero = Integer.parseInt(teclado.nextLine());
        System.out.println("Has escrito: " + numero);
    }
}

    Para leer texto utiliza teclado.nextLine() y para un decimal, Double.parseDouble(teclado.nextLine()), escribiendo el punto como separador decimal. Por ahora puedes suponer que se introduce un dato del tipo solicitado; las comprobaciones del enunciado se refieren a sus valores.

    Qué debes hacer

    Declara dos variables locales de tipo int, numero1 y numero2. Compara sus valores y muestra exactamente uno de estos mensajes:

    • Si el primero es mayor: El primer número es mayor.
    • Si el segundo es mayor: El segundo número es mayor.
    • Si coinciden: Los dos números son iguales.

    Resuelve la comparación mediante condicionales, sin utilizar Math.max().

    Pruebas

    Ejecuta el programa con 8 y 3, 3 y 8, 5 y 5 y -2 y -7. Antes de ejecutar, anota qué mensaje esperas.

    Nombre del proyecto del ejercicio: UT3Ejer1Comparacion

    3.8 Juego de dados

    Decide quién gana una partida en la que un trío tiene prioridad sobre la suma.

    Qué debes hacer

    Representa a dos participantes mediante sus nombres y seis variables enteras locales: tres dados por participante. Todo el programa se desarrolla dentro de main.

    1. Asigna inicialmente valores entre 1 y 6 para poder probar las reglas.
    2. Muestra los tres dados y la suma de cada participante.
    3. Si solo una persona tiene los tres dados iguales, gana esa persona, independientemente de las sumas.
    4. Si ambas tienen trío, gana quien tenga el valor de dado más alto; si los tríos son iguales, hay empate.
    5. Si ninguna tiene trío, gana la suma mayor; si las sumas coinciden, hay empate.

    Cuando funcionen las decisiones, sustituye las asignaciones por tiradas con Random o Math.random(). No necesitas arrays ni una clase Jugador.

    Pruebas

    Comprueba 2, 2, 2 contra 6, 6, 5; dos tríos diferentes; dos tríos iguales; y dos tiradas sin trío con la misma suma.

    3.9 Batalla de robots

    Actualiza la vida de dos robots y decide si pueden continuar el combate.

    Qué debes hacer

    En main, representa a cada robot mediante variables locales para nombre, vida, ataque y defensa, diferenciándolas con los sufijos 1 y 2. La vida inicial será 100 y los valores de ataque y defensa serán enteros positivos.

    1. El robot 1 ataca al robot 2. Solo causa daño si su ataque supera la defensa rival.
    2. El daño es la diferencia entre ataque y defensa. Resta ese daño a la vida del defensor, sin dejarla por debajo de cero.
    3. Muestra el daño causado y la vida restante. Si el defensor llega a cero, anuncia su derrota.
    4. Si el robot 2 sigue vivo, responde una vez aplicando las mismas reglas al robot 1.
    5. Muestra el estado de ambos al terminar el intercambio.

    No declares una clase Robot ni un método de combate. Las comprobaciones y modificaciones de vida deben estar dentro de main.

    Pruebas y ampliación con bucles

    Prueba ataque inferior, igual y superior a la defensa, y un golpe que elimine al defensor. Después, como ampliación, repite los intercambios con while hasta que alguien pierda o se alcancen 20 rondas. Si ambos siguen vivos al llegar al límite, declara empate; así también termina un combate en el que nadie puede causar daño.

    Nombre del proyecto del ejercicio: UT3Ejer9BatallaRobots

    3.10 Colisión entre rectángulos

    Combina comparaciones en dos ejes para detectar si dos rectángulos se tocan o se superponen.

    Qué debes hacer

    Dentro de main, declara ocho variables locales: x1, y1, anchura1, altura1 y las cuatro equivalentes para el segundo rectángulo. No crees objetos Rectangulo.

    Considera x e y como las coordenadas mínimas del rectángulo. Su intervalo horizontal va desde x hasta x + anchura y el vertical, desde y hasta y + altura.

    • Si alguna anchura o altura no es positiva, informa de que las dimensiones no son válidas.
    • Para datos válidos, comprueba si los intervalos se tocan o superponen en cada eje.
    • Solo hay colisión si esto sucede en ambos ejes. El contacto de bordes o de una esquina cuenta como colisión.

    Guarda el resultado en boolean hayColision y muestra un mensaje mediante un condicional.

    Pruebas

    Comprueba separación horizontal, separación vertical, superposición parcial, un rectángulo dentro de otro, contacto de bordes y contacto en una esquina. Prueba también coordenadas negativas y dimensiones no válidas.

    3.16 Cálculo del factorial

    Utiliza un bucle y un acumulador para calcular un producto.

    Qué debes hacer

    El factorial de un entero no negativo n, escrito n!, es el producto de los enteros desde 1 hasta n. Por definición, 0! = 1. Por ejemplo, 5! = 1 × 2 × 3 × 4 × 5 = 120.

    1. Solicita un entero entre 0 y 20. Si está fuera de ese intervalo, vuelve a pedirlo mediante un bucle.
    2. Calcula el factorial con un bucle for y una variable acumuladora de tipo long.
    3. Muestra cada factor y el producto acumulado, y finalmente el resultado.
    4. Escribe después una segunda versión empleando while.

    Realiza todo dentro de main, sin recursividad ni métodos propios. El límite de 20 permite que el resultado quepa en un long. Piensa con qué valor debe comenzar un acumulador que multiplica.

    Pruebas

    Prueba 0, 1, 5 y 20. Introduce primero -1 o 21 para comprobar que vuelve a solicitar un valor.

    Nombre del proyecto del ejercicio: UT3Ejer16Factorial

    3.17 Serie de Fibonacci

    Calcula una sucesión conservando únicamente los dos valores anteriores.

    Qué debes hacer

    La sucesión comienza con F(0) = 0 y F(1) = 1. Cada término siguiente es la suma de los dos anteriores: 0, 1, 1, 2, 3, 5, 8, 13....

    1. Solicita una posición entera n entre 0 y 92. Repite la petición mientras el valor no sea válido.
    2. Muestra los términos desde la posición 0 hasta la posición n, ambas incluidas, mediante un bucle.
    3. Indica al final cuál es el valor de F(n).

    Trabaja solo dentro de main, con variables long para los términos y una variable temporal para actualizar los valores sin perder información. No utilices recursividad, arrays ni métodos auxiliares.

    El límite evita que el término solicitado supere la capacidad de long. Ten cuidado: tampoco debes calcular un término posterior fuera de rango que no vayas a mostrar.

    Pruebas

    Prueba n = 0, 1, 2, 7 y 92. Para n = 7 deben aparecer ocho términos, porque comenzamos a contar en la posición cero.

    Nombre del proyecto del ejercicio: UT3Ejer17Fibonacci

    3.18 Reproductor de música

    Simula un reproductor con menú, estado y batería, íntegramente dentro de main.

    Datos de la simulación

    Representa dos canciones mediante variables locales, sin clases ni arrays:

    • Canción 1: «Bohemian Rhapsody», 360 segundos, género Rock.
    • Canción 2: «Imagine», 183 segundos, género Pop.
    • Un contador de reproducciones completas para cada canción, inicialmente a cero.

    El reproductor comienza apagado, con batería al 100 % y sin canción seleccionada. Necesitarás variables para encendido, bateria, cancionActual (0, 1 o 2), tiempoRestante y los segundos reproducidos desde el último consumo de batería.

    Menú y reglas

    Repite un menú mediante do-while y procesa las opciones con condicionales o switch:

    1. Encender: solo es posible si queda batería.
    2. Apagar: conserva la canción y el tiempo pendiente, pero impide reproducir o cambiar de canción.
    3. Seleccionar canción: solicita 1 o 2. Debe estar encendido y disponer de más de 5 puntos de batería. La selección, incluso si se elige la misma canción, consume 5 puntos, reinicia su tiempo restante y pone a cero los segundos parciales de consumo. Si no se puede realizar, no modifica nada.
    4. Reproducir: solicita una cantidad positiva de segundos. Solo se permite si está encendido y hay una canción con tiempo pendiente.
    5. Consultar información: muestra estado, batería, canción, género, tiempo restante y los dos contadores de reproducciones completas.
    6. Salir: utiliza la opción 0 para terminar el programa.

    Durante la reproducción, utiliza un bucle que simule los segundos de uno en uno, sin esperas reales. Cada segundo reduce el tiempo restante y aumenta el contador de segundos parciales. Cada 60 segundos acumulados consume 1 punto de batería y reinicia ese contador. Si varias peticiones reproducen la misma canción, los segundos parciales se conservan.

    Detén la reproducción cuando se alcance el tiempo solicitado, termine la canción o se agote la batería. Si termina la canción, aumenta una sola vez su contador de reproducciones completas. Si la batería llega a cero, apaga el reproductor. Ningún tiempo ni la batería pueden quedar en negativo.

    Los valores de opción desconocidos deben producir un aviso. No crees clases Cancion o ReproductorMusica, ni métodos adicionales.

    Pruebas

    Intenta reproducir estando apagado y sin selección. Después selecciona una canción, reproduce 30 segundos y luego otros 30, y comprueba el consumo. Solicita más tiempo del que queda y verifica que la reproducción completa se cuenta una sola vez. Prueba también tiempo cero, una canción desconocida y el agotamiento de la batería.

    Nombre del proyecto del ejercicio: UT3Ejer18ReproductorMusical

    3.19 Puesto de lotería

    Simula la venta de boletos y busca quién queda más cerca del número ganador.

    Datos iniciales

    Representa en main a Ana, Luis y Carlos con tres grupos de variables locales para nombre, dinero y boleto. Sus saldos iniciales son 50, 11 y 100 euros, respectivamente.

    Cada boleto cuesta 20 euros. El número ganador y los boletos válidos serán enteros aleatorios entre 10000 y 99999, ambos incluidos. Utiliza Random o Math.random(). Inicializa los boletos con -99999 para representar que todavía no se han comprado.

    Qué debes hacer

    1. Genera el número ganador, pero no lo muestres hasta completar las ventas.

    3. Muestra el nombre, el boleto o el mensaje «sin boleto», y el saldo restante de cada persona.
    4. Revela el número ganador y calcula, con Math.abs(), la distancia de cada boleto válido a ese número.
    5. Muestra todas las personas con la menor distancia. Puede haber empate. Si la distancia es cero, indica que se ha acertado el número.
    6. Si nadie pudo comprar, muestra que no hay participantes. Nunca incluyas un boleto -99999 en la búsqueda del ganador.

    Como ampliación, utiliza un for de tres iteraciones para procesar las compras: selecciona con condicionales los datos de la persona correspondiente y actualiza sus variables. No necesitas arrays.

    3.20 Simulación de carrera de coches

    Combina aleatoriedad, bucles, acumuladores y clasificación para simular una carrera.

    Datos y reglas

    Dentro de main, representa tres coches mediante variables locales para nombre, velocidad actual, distancia total y posición. Comienzan con distancia cero. No crees clases Coche o Carrera.

    La simulación tendrá cinco rondas. En cada una, los tres coches circulan durante una hora a una nueva velocidad aleatoria entera entre 100 y 200 km/h, ambos incluidos. Por tanto, en cada ronda cada coche suma a su distancia tantos kilómetros como indique su velocidad. Estas rondas son intervalos de tiempo, no vueltas a una pista de longitud fija.

    Qué debes hacer

    1. Utiliza un for para recorrer las cinco rondas.
    2. Genera las tres velocidades y actualiza las tres distancias antes de calcular posiciones.
    3. La posición de un coche será 1 más la cantidad de rivales que tengan una distancia estrictamente mayor que la suya.
    4. Muestra en cada ronda su número y, para cada coche, nombre, velocidad, distancia y posición.
    5. Al terminar, muestra el podio ordenado por posiciones y felicita a todos los coches que compartan la primera posición.

    Los empates comparten posición. Por ejemplo, con distancias 900, 900 y 850, las posiciones son 1, 1 y 3. Puedes mostrar el podio recorriendo las posiciones del 1 al 3 y comprobando qué coches ocupan cada una, sin arrays ni ordenaciones de biblioteca.

    Pruebas

    Prueba primero velocidades fijas para comprobar sumas y posiciones. Incluye un cambio de líder, dos coches empatados y tres empatados. Después activa la generación aleatoria y comprueba que cada distancia final está entre 500 y 1000 km.

    Nombre del proyecto del ejercicio: UT3Ejer20CarreraCoches

    3.21 Calculadora con switch
