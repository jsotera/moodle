    2.1 Comprender clases dadas

    Antes de utilizar objetos en Main, necesitamos aprender a leer una clase y reconocer sus partes principales.

    Objetivo

    En esta actividad no vamos a diseñar clases desde cero. Vamos a observar dos clases ya creadas, Persona y Pelicula, para entender cómo están compuestas.

    Después responderemos preguntas sobre atributos, constructores, métodos, getters y setters. La idea es distinguir qué partes de la clase almacenan información, qué partes permiten crear objetos y qué partes permiten usar o modificar esos objetos.

    Proyecto base

    Descarga el proyecto Maven base y ábrelo con IntelliJ IDEA. El proyecto contiene las clases Persona y Pelicula ya creadas, además de una clase Main mínima para empezar a probar.

    La estructura de paquetes es la siguiente:

    • edu.masanz.da.ut2.modelo: clases Persona y Pelicula.
    • edu.masanz.da.ut2.app: clase Main.

    En este primer ejercicio no debes modificar las clases. Tu tarea principal es leerlas, entender sus partes y responder a las preguntas.

    Descargar proyecto base

    Preguntas de comprensión

    1. ¿Qué sección de cada clase representa los atributos?

    Cuidado, spoiler

    Los atributos son las variables declaradas al inicio de cada clase con private. Representan el estado que guarda cada objeto.

    private String nombre;
private int edad;
private String profesion;

    2. ¿Cuántos atributos tiene la clase Persona? ¿Y la clase Pelicula?

    Cuidado, spoiler

    Persona tiene 3 atributos: nombre, edad y profesion.

    Pelicula tiene 7 atributos: titulo, anioEstreno, director, actrizPrincipal, actorPrincipal, duracionMinutos y estrenada.

    3. ¿De cuántas maneras diferentes podemos crear una Persona?

    Cuidado, spoiler

    De 2 maneras, porque la clase tiene 2 constructores.

    Persona persona1 = new Persona("Ane");
Persona persona2 = new Persona("Ane", 32, "Directora");

    4. ¿De cuántas maneras diferentes podemos crear una Pelicula?

    Cuidado, spoiler

    De 2 maneras, porque la clase tiene 2 constructores.

    Persona directora = new Persona("Ane", 32, "Directora");
Persona actriz = new Persona("Nerea", 28, "Actriz");
Persona actor = new Persona("Iker", 30, "Actor");

Pelicula pelicula1 = new Pelicula("La noche del código", directora);
Pelicula pelicula2 = new Pelicula("La noche del código", 2026,
        directora, actriz, actor, 120);

    5. ¿Qué constructores piden menos información? ¿Qué valores se asignan por defecto en esos casos?

    Cuidado, spoiler

    Los constructores cortos son Persona(String nombre) y Pelicula(String titulo, Persona director).

    En Persona, la edad queda en 0 y la profesión en "Sin indicar". En Pelicula, el año y la duración quedan en 0, y estrenada queda en false.

    6. ¿Qué métodos sirven únicamente para obtener información de los atributos?

    Cuidado, spoiler

    Son los getters: getNombre, getEdad, getProfesion, getTitulo, getAnioEstreno, getDirector, getActrizPrincipal, getActorPrincipal, getDuracionMinutos e isEstrenada.

    String titulo = pelicula.getTitulo();
int edad = persona.getEdad();
boolean yaEstrenada = pelicula.isEstrenada();

    7. ¿Qué métodos sirven únicamente para modificar directamente atributos?

    Cuidado, spoiler

    Son los setters, los métodos que empiezan por set. Asignan directamente un nuevo valor a un atributo.

    persona.setEdad(33);
pelicula.setTitulo("Nuevo título");
pelicula.setDuracionMinutos(125);

    8. ¿Por qué en Pelicula aparece isEstrenada() en lugar de getEstrenada()?

    Cuidado, spoiler

    Porque estrenada es un atributo boolean. En Java es habitual que los getters de booleanos empiecen por is.

    9. ¿Qué métodos realizan acciones o modifican el estado de los objetos?

    Cuidado, spoiler

    cumplirAnios, presentarse, estrenar, retrasarEstreno y obtenerResumen son métodos de acción o comportamiento.

    persona.cumplirAnios();
pelicula.estrenar(2026);
pelicula.retrasarEstreno();

    10. ¿Qué atributos de Pelicula son de tipo Persona?

    Cuidado, spoiler

    Son director, actrizPrincipal y actorPrincipal.

    private Persona director;
private Persona actrizPrincipal;
private Persona actorPrincipal;

    11. ¿Qué significa que una película tenga un director, una actrizPrincipal y un actorPrincipal de tipo Persona?

    Cuidado, spoiler

    Significa que la película no guarda solo textos para esas personas, sino referencias a objetos completos de la clase Persona.

    12. ¿Qué método de Pelicula utiliza un método de la clase Persona?

    Cuidado, spoiler

    obtenerResumen() utiliza director.getNombre(), es decir, llama a un método de un objeto Persona.

    return titulo + " es una película dirigida por "
        + director.getNombre() + ".";

    13. ¿Qué diferencia hay entre cambiar el título con setTitulo(...) y estrenar una película con estrenar(...)?

    Cuidado, spoiler

    setTitulo(...) solo cambia un atributo. estrenar(...) modifica dos partes del estado: el año de estreno y si la película está estrenada.

    pelicula.setTitulo("Otro título");
pelicula.estrenar(2026);

    14. ¿Qué información mínima necesitas para crear una película usando el constructor más corto?

    Cuidado, spoiler

    Necesitas un titulo y un director.

    Persona directora = new Persona("Ane");
Pelicula pelicula = new Pelicula("La noche del código", directora);

    15. ¿Qué información mínima necesitas para crear una persona usando el constructor más corto?

    Cuidado, spoiler

    Necesitas un nombre.

    Persona persona = new Persona("Ane");

    Pista antes de mirar las respuestas

    Intenta clasificar cada parte de las clases en una de estas categorías:

    • Atributos: guardan el estado del objeto.
    • Constructores: permiten crear objetos.
    • Getters: devuelven información.
    • Setters: modifican directamente atributos.
    • Métodos de acción: hacen algo más significativo que devolver o asignar un valor.

    2.2 Carrera de coches y tiempos

    Desarrolla una aplicación Java que simule una pequeña prueba en circuito utilizando las clases del paquete modelo vistas en clase.

    Objetivo

    El objetivo de este ejercicio es practicar la creación de objetos, la llamada a métodos y la consulta del estado de las instancias desde la clase Main.

    No debes modificar las clases del paquete modelo. Toda la lógica del ejercicio se debe escribir en el método main.

    Enunciado

    Crea una aplicación que simule una carrera sencilla con las siguientes condiciones:

    • Crea 1 circuito y 2 coches.
    • Cada coche debe entrar en el circuito.
    • Cada coche debe acelerar 3 veces consecutivas.
    • En cada aceleración se debe aplicar una velocidad aleatoria de entre 1 y 50 km/h.
    • Calcula y muestra por consola el tiempo total, en segundos, que ha permanecido cada coche en el circuito.

    Salida esperada

    La salida no tiene por qué ser exactamente igual, ya que las velocidades serán aleatorias, pero debe mostrar información clara sobre cada coche:

    Coche 1
Velocidades aplicadas: 32 km/h, 14 km/h, 47 km/h
Tiempo total en el circuito: 125 segundos

Coche 2
Velocidades aplicadas: 21 km/h, 50 km/h, 18 km/h
Tiempo total en el circuito: 139 segundos

    Si las clases del modelo ya ofrecen métodos para mostrar esta información, utilízalos. Si no, combina llamadas a métodos y mensajes con System.out.println.

    Pistas

    • Recuerda importar las clases necesarias del paquete modelo.
    • Puedes generar números aleatorios con Math.random() o con la clase Random.
    • Comprueba qué constructores tiene cada clase antes de crear los objetos.
    • Revisa qué métodos modifican el estado del coche y cuáles devuelven información.

    Nombre del proyecto del ejercicio: CarreraCoches

    2.3 Arena de robots

    Desarrolla una simulación de combates utilizando dos clases dadas: Robot y Arena.

    Proyecto base

    Descarga el proyecto Maven base y ábrelo con IntelliJ IDEA. El proyecto contiene las clases Robot y Arena ya creadas en el paquete modelo, además de una clase Main preparada para completar el ejercicio.

    Descargar proyecto base

    Objetivo

    El objetivo es practicar la creación de objetos, el uso de constructores, la llamada a métodos y el trabajo con objetos que se pasan como parámetro a otros métodos.

    No debes modificar las clases Robot ni Arena. Toda la lógica del ejercicio debe escribirse en el método main.

    Enunciado

    Crea una aplicación que simule una arena de combate con las siguientes condiciones:

    • Crea una instancia de Arena.
    • Crea 6 robots utilizando los constructores disponibles.
    • Inscribe los 6 robots en la arena.
    • Realiza varias rondas de combate llamando al método comenzarCombate.
    • Muestra por consola el podio actual de la arena.

    Parte avanzada

    Después de mostrar el primer podio, realiza una segunda fase:

    • Guarda en variables los tres robots que van primero, segundo y tercero en la clasificación.
    • Restablece la arena con el método restablecer.
    • Inscribe únicamente esos tres robots ganadores.
    • Realiza 10 rondas de combate nuevas.
    • Muestra el podio final.

    No debes modificar manualmente la vida de los robots. Los tres robots clasificados deben continuar con la vida que tenían al terminar la primera fase.

    Salida esperada

    La salida puede variar porque algunos valores y combates son aleatorios, pero debería mostrar mensajes similares a estos:

    Comienza el combate entre Ares y Neko.
Ares ataca a Neko y causa 8 puntos de danio.
Neko ataca a Ares y causa 3 puntos de danio.

Podio actual:
1. Robot{nombre='Ares', vida=97, fuerza=6, defensa=8}
2. Robot{nombre='Neko', vida=92, fuerza=4, defensa=5}
3. Robot{nombre='Luna', vida=88, fuerza=9, defensa=3}

    Pistas

    • Revisa los constructores de Robot antes de crear los objetos.
    • Si utilizas el constructor vacío, recuerda asignar después valores válidos con los setters antes de combatir.
    • Utiliza variables para conservar la referencia a los robots que quieras reutilizar.
    • Para repetir combates, puedes usar varias llamadas seguidas o un bucle for.
    • Recuerda que restablecer vacía la arena, pero no crea robots nuevos ni cambia la vida de los robots existentes.

    Nombre del proyecto del ejercicio: ArenaRobots

    2.4 Red social simple

    Desarrolla una pequeña simulación de red social utilizando dos clases dadas: Usuario y RedSocial.

    Proyecto base

    Descarga el proyecto Maven base y ábrelo con IntelliJ IDEA. El proyecto contiene las clases Usuario y RedSocial documentadas con Javadoc, además de una clase Main preparada para completar el ejercicio.

    Descargar proyecto base

    Objetivo

    El objetivo es practicar el uso de objetos relacionados entre sí, llamadas a métodos con parámetros de tipo objeto y lectura de documentación Javadoc.

    En este ejercicio todavía no se utilizan listas, arrays ni colecciones. Cada usuario puede seguir como máximo a tres usuarios mediante los atributos sigoA1, sigoA2 y sigoA3.

    Reglas del modelo

    • La clase Usuario representa los datos de cada usuario: nick, muro y hasta tres usuarios seguidos.
    • La clase RedSocial es la encargada de publicar mensajes, asignar seguidores y consultar muros.
    • Siempre que se usa la red social, el primer parámetro de sus métodos es el usuario que está realizando la acción.
    • No debes modificar directamente los atributos internos de seguimiento desde Main.

    Enunciado

    Crea una aplicación que simule una red social sencilla con las siguientes condiciones:

    • Crea una instancia de RedSocial.
    • Crea al menos 5 usuarios con distintos nicks.
    • Publica varios mensajes en los muros de diferentes usuarios.
    • Haz que algunos usuarios sigan a otros usuarios.
    • Consulta el muro propio de al menos un usuario.
    • Consulta el muro de seguidos de al menos dos usuarios distintos.
    • Muestra por consola a quién sigue cada usuario principal que hayas utilizado.

    Pruebas obligatorias

    Además del funcionamiento normal, comprueba los siguientes casos:

    • Un usuario intenta seguir a más de 3 usuarios.
    • Un usuario intenta seguirse a sí mismo.
    • Un usuario intenta seguir dos veces a la misma persona.
    • Un usuario deja de seguir a otra persona y después consulta de nuevo su muro de seguidos.

    Salida esperada

    La salida puede variar según los usuarios y mensajes que crees, pero debería ser clara y parecida a esta:

    ane sigue a:
- markel
- june
- irati

Muro de usuarios seguidos por ane
--- markel ---
markel: Hoy estoy repasando clases en Java.

--- june ---
june: Me falta entender bien los objetos como parametros.

ane no puede seguir a mas usuarios.
ane no puede seguirse a si mismo.

    Pistas

    • Lee el Javadoc de cada método antes de utilizarlo.
    • Recuerda que una variable de tipo Usuario guarda una referencia a un objeto.
    • No necesitas crear clases nuevas ni modificar Usuario o RedSocial.
    • Para ver mejor el resultado, separa las pruebas con mensajes de consola.

    Nombre del proyecto del ejercicio: RedSocialSimple

    2.5 Coche, accidente y referencias

    Trabaja con objetos relacionados entre sí y observa una de las ideas más importantes de la programación orientada a objetos: las variables guardan referencias a objetos.

    Proyecto base

    Descarga el proyecto Maven base y ábrelo con IntelliJ IDEA. El proyecto contiene las clases Persona y Coche documentadas con Javadoc, además de una clase Main preparada para completar la actividad.

    Descargar proyecto base

    Objetivo

    El objetivo es utilizar objetos de tipo Persona dentro de un objeto de tipo Coche y comprobar que, cuando el coche modifica una persona, también cambia el objeto que teníamos guardado en una variable del Main.

    No debes modificar las clases Persona ni Coche. Toda la lógica de prueba debe escribirse en el método main.

    Reglas del modelo

    • Una Persona tiene nombre y lesion.
    • Un Coche puede tener conductor, copiloto, pasajero 1 y pasajero 2.
    • El conductor no puede entrar también como pasajero.
    • Los pasajeros se van colocando por orden: copiloto, pasajero 1 y pasajero 2.
    • Si el coche no está arrancado, no puede acelerar.
    • Cuando ocurre un accidente, el coche asigna lesiones a las personas que van dentro.

    Enunciado

    Crea una aplicación de prueba con las siguientes condiciones:

    • Crea al menos 5 personas.
    • Crea un coche indicando su modelo.
    • Asigna una persona como conductor.
    • Intenta asignar al conductor también como pasajero y observa qué ocurre.
    • Asigna varios pasajeros hasta llenar el coche.
    • Intenta añadir una persona más cuando el coche ya esté lleno.
    • Muestra la descripción del coche por consola.
    • Intenta acelerar antes de arrancar el coche.
    • Arranca el coche, acelera varias veces y provoca un accidente.
    • Consulta las lesiones desde las variables de tipo Persona creadas en Main.

    La trampa importante

    Después del accidente, no consultes únicamente la descripción del coche. Llama también al método informarSobreLesion desde las variables originales de cada persona.

    Si una persona estaba dentro del coche, su lesión habrá cambiado aunque la estés consultando desde una variable del Main. Eso ocurre porque el coche y el Main están trabajando con el mismo objeto.

    Salida esperada

    La salida puede variar según los nombres y velocidades que utilices, pero debería mostrar mensajes similares a estos:

    No se puede acelerar porque el coche no esta arrancado.
El coche ha arrancado.
El coche acelera hasta 40 km/h.
El coche acelera hasta 75 km/h.
El coche ha tenido un accidente a 75 km/h.
El coche se ha detenido.
Ane sufre la siguiente lesion: fractura leve.
Markel sufre la siguiente lesion: fractura leve.

    Parte avanzada

    Después de tener un accidente:

    • Prueba a curar alguno de los pasajeros (restableciendo las lesiones).
    • Muestra la descripción del coche por persona.
    • ¿Qué ha ocurrido?
    • Realiza una depuración paso a paso para visualizar mediante el plugin Java Visualizer lo que está ocurriendo.

    Pistas

    • Lee el Javadoc de cada método antes de utilizarlo.
    • Guarda cada persona en una variable distinta para poder consultarla después del accidente.
    • Utiliza descripcion antes y después de asignar pasajeros para comprobar el estado del coche.
    • Prueba diferentes velocidades para ver cómo cambia el tipo de lesión.

    Nombre del proyecto del ejercicio: CocheAccidente

    2.6 Consolas prestadas y referencias

    Trabaja con tres modelos relacionados entre sí: Persona, Consola y VideoJuego.

    Proyecto base

    Descarga el proyecto Maven base y ábrelo con IntelliJ IDEA. El proyecto contiene las clases Persona, Consola y VideoJuego documentadas con Javadoc, además de una clase Main preparada para completar la actividad.

    Descargar proyecto base

    Objetivo

    El objetivo es observar cómo varios objetos pueden quedar conectados entre sí mediante referencias: una persona usa una consola, la consola tiene un propietario fijo y la consola ejecuta un videojuego concreto.

    No debes modificar las clases del paquete modelo. Toda la lógica de prueba debe escribirse en el método main.

    Reglas del modelo

    • Una Persona tiene nombre, estado y una consolaEnUso.
    • Una Consola tiene un propietario fijo, un modelo, un estado operativo y un videojuego insertado.
    • El propietario de una consola no cambia aunque la consola se preste a otra persona.
    • Una consola solo puede utilizarse a través de métodos de una Persona.
    • Para utilizar una consola, primero debe tener un videojuego insertado.
    • Cada vez que se usa un juego, aumenta su contador de usos.
    • Cada uso tiene un 50% de probabilidad de estropear la consola.
    • Si un mismo videojuego se utiliza más de 3 veces, la consola se estropea automáticamente.
    • Cuando una consola se estropea, su propietario pasa a tener el estado enfadado.

    Enunciado

    Crea una aplicación de prueba con las siguientes condiciones:

    • Crea al menos 3 personas.
    • Crea una consola cuyo propietario sea una de esas personas.
    • Crea al menos 2 videojuegos.
    • Haz que el propietario reciba su consola, inserte un videojuego y la utilice.
    • Presta la consola a otra persona y vuelve a utilizarla desde esa persona.
    • Comprueba que la consola sigue perteneciendo a la persona propietaria original.
    • Utiliza varias veces el mismo videojuego hasta provocar que la consola se estropee.
    • Consulta el estado de la persona propietaria desde su variable original del Main.

    La trampa importante

    La persona que usa la consola no tiene por qué ser su propietaria. Si la consola se rompe mientras la está usando otra persona, quien se enfada es la persona propietaria original.

    Ese cambio se verá también si consultas el objeto Persona original que creaste en Main, porque es la misma referencia que guarda la consola como propietaria.

    Pruebas avanzadas

    • Intenta utilizar una consola sin haber insertado ningún videojuego.
    • Inserta un videojuego, presta la consola y comprueba que el videojuego insertado sigue dentro.
    • Usa el mismo videojuego desde distintas personas y observa que su contador de usos sigue aumentando.
    • Crea una segunda consola y compara qué propietario se enfada cuando se estropea cada una.

    Salida esperada

    La salida puede variar porque existe probabilidad de avería, pero debería mostrar mensajes similares a estos:

    Ane tiene ahora en uso la consola RetroBox.
Se ha insertado Pixel Kart en RetroBox.
Ejecutando Pixel Kart en RetroBox. Uso numero 1.
Ane ha prestado la consola a Markel.
Ejecutando Pixel Kart en RetroBox. Uso numero 2.
La consola se ha roto por mala suerte.
La consola RetroBox se ha estropeado.
Ane se ha enfadado.
Ane esta enfadado.

    Pistas

    • Lee el Javadoc antes de utilizar cada método.
    • Utiliza toString para observar el estado de personas, consolas y videojuegos.
    • No confundas propietario con consolaEnUso.
    • Si la consola se rompe demasiado pronto por probabilidad, vuelve a ejecutar el programa.

    Nombre del proyecto del ejercicio: ConsolasPrestadas

    2.7 Piedra, papel o tijera

    Desarrolla una simulación sencilla de piedra, papel o tijera utilizando dos clases dadas: Persona y Juego.

    Proyecto base

    Descarga el proyecto Maven base y ábrelo con IntelliJ IDEA. El proyecto contiene las clases Persona y Juego documentadas con Javadoc, además de una clase Main preparada para completar la actividad.

    Descargar proyecto base

    Objetivo

    El objetivo es practicar el uso de objetos relacionados de una forma más sencilla: dos personas participan en un juego, y la clase Juego se encarga de asignar jugadas, decidir el resultado y actualizar los marcadores.

    No debes modificar las clases del paquete modelo. Toda la lógica de prueba debe escribirse en el método main.

    Reglas del modelo

    • Una Persona tiene nombre, jugada actual, partidas ganadas, partidas perdidas y partidas empatadas.
    • Un Juego tiene dos personas participantes.
    • Cada vez que se llama a jugar, el juego asigna automáticamente una jugada a cada persona.
    • La clase Juego decide quién gana y actualiza los contadores de ambas personas.
    • Desde Main no debes modificar directamente los marcadores.

    Enunciado

    Crea una aplicación de prueba con las siguientes condiciones:

    • Crea dos personas con nombres distintos.
    • Crea una instancia de Juego con esas dos personas.
    • Ejecuta varias partidas llamando al método jugar.
    • Muestra el marcador utilizando el método obtenerMarcador.
    • Muestra también por consola las dos variables originales de tipo Persona.

    La idea importante

    La clase Juego modifica los contadores de las personas que recibió en el constructor. Cuando después imprimas las variables originales de Main, verás esos cambios porque son los mismos objetos.

    Pruebas avanzadas

    • Ejecuta 10 partidas usando un bucle for.
    • Crea un segundo juego reutilizando una de las personas anteriores contra una persona nueva.
    • Comprueba si el marcador de la persona reutilizada conserva las partidas anteriores.

    Salida esperada

    La salida cambiará porque las jugadas son aleatorias, pero debería mostrar mensajes similares a estos:

    Ane juega piedra.
Markel juega tijera.
Gana Ane.

Ane juega papel.
Markel juega papel.
La partida termina en empate.

Persona{nombre='Ane', jugadaActual='papel', ganadas=1, perdidas=0, empatadas=1}
Persona{nombre='Markel', jugadaActual='papel', ganadas=0, perdidas=1, empatadas=1}

    Pistas

    • Lee el Javadoc de jugar y obtenerMarcador.
    • No necesitas pedir datos por teclado.
    • Recuerda que cada llamada a jugar representa una partida completa.
    • Observa cómo cambian los objetos Persona aunque los cambios los haga la clase Juego.

    Nombre del proyecto del ejercicio: PiedraPapelTijera
