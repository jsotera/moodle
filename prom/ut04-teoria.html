    4.1 Clases, objetos y estado

    Una clase describe un tipo de elemento; cada objeto tiene su propio estado. Vamos a construir y observar nuestros primeros objetos.

    De muchas variables a una clase

    Queremos guardar el nombre y los puntos de dos jugadores. Con variables sueltas podríamos escribir:

    String nombre1 = "Ana";
int puntos1 = 10;
String nombre2 = "Iker";
int puntos2 = 20;

    Cada vez que añadimos un jugador necesitamos otras variables. Una clase agrupa la información y las acciones de un mismo tipo de elemento. Un objeto es un elemento concreto creado a partir de esa clase.

    Concepto En nuestro ejemplo
    Clase Jugador: define qué información tendrá cada jugador.
    Objeto El jugador de Ana o el jugador de Iker.
    Atributos / estado nombre y puntos: los datos de cada jugador.
    Métodos / comportamiento Las acciones que programaremos, como sumar puntos.

    Nuestra primera clase

    Jugador.java

    public class Jugador {
    String nombre;
    int puntos;
}

    Guarda la clase en Jugador.java. El nombre del archivo debe coincidir con el de la clase pública. Las llaves delimitan su cuerpo. Cada atributo tiene un tipo y un nombre. Usamos mayúscula inicial para las clases y minúscula inicial para atributos y variables.

    En este primer ejemplo los atributos no tienen modificador de acceso: pueden utilizarse desde clases del mismo paquete. Lo hacemos para observar los objetos; más adelante los protegeremos con private .

    Crear y utilizar dos objetos

    Main.java

    public class Main {
    public static void main(String[] args) {
        Jugador j1 = new Jugador();
        Jugador j2 = new Jugador();

        j1.nombre = "Ana";
        j1.puntos = 10;
        j2.nombre = "Iker";
        j2.puntos = 20;

        System.out.println(j1.nombre + ": " + j1.puntos);
        System.out.println(j2.nombre + ": " + j2.puntos);
    }
}

    Crea ambos archivos en el mismo paquete y ejecuta Main. Cada new Jugador() crea un objeto. El punto permite acceder a un miembro del objeto. Cambiar j1.puntos no cambia los puntos de j2.

    La cabecera main(String[] args) se mantiene como ya la conoces. No utilizaremos args ni estudiaremos arrays en esta unidad.

    Declarar no es crear

    Código Qué ocurre
    Jugador j1; Declara una variable local. Todavía no tiene un valor asignado.
    j1 = new Jugador(); Crea un objeto y asigna su referencia a j1.
    Jugador j1 = new Jugador(); Hace ambas cosas en una instrucción.
    Jugador j1 = null; La variable tiene valor, pero no apunta a ningún objeto.

    Una variable local sin inicializar no puede utilizarse: el compilador avisa. Si contiene null y accedemos a j1.nombre, se produce una NullPointerException. Son problemas diferentes.

    Los atributos sí reciben valores iniciales de Java: int vale 0, boolean vale false y una referencia como String vale null. Una variable local no recibe automáticamente esos valores.

    Dos referencias pueden señalar el mismo objeto

    Jugador j1 = new Jugador();
j1.nombre = "Ana";
j1.puntos = 10;
Jugador j2 = j1;
j2.puntos = 30;
System.out.println(j1.puntos);

    Antes de ejecutarlo, predice el resultado. ¿Cuántos new hay?

    Ver solución orientativa

    Muestra 30. Solo se ha creado un objeto: j1 y j2 se refieren al mismo jugador. La asignación copia la referencia; no duplica el objeto.

    Error frecuente: creer que Jugador j2 = j1; crea un jugador independiente. Para crear otro objeto necesitas otro new .

    Practica paso a paso

    • Crea una clase Lampara con String ubicacion y boolean encendida.
    • Crea dos lámparas, enciende solo una y muestra el estado de ambas.
    • Asigna la primera referencia a una tercera variable. Cambia su estado desde esa variable y comprueba qué ocurre.
    • Coloca un punto de ruptura después de crear los objetos y observa sus atributos en el depurador.

    Cambia de contexto

    Una estación registra la temperatura de dos aulas. Propón una clase con nombre del aula y temperatura, crea dos objetos y modifica solo uno. No uses arrays: bastan dos variables.

    Recuerda

    • La clase define atributos y métodos; los objetos son instancias de esa clase.
    • Declarar una referencia y crear un objeto son operaciones diferentes.
    • Dos objetos pueden tener estados diferentes; dos referencias pueden apuntar al mismo objeto.

    4.2 Métodos y comportamiento de los objetos

    Un método expresa una acción o una consulta. Aprenderemos a pasar datos, devolver resultados y decidir qué responsabilidad pertenece al objeto.

    El objeto también puede actuar

    Hasta ahora Main cambiaba los puntos directamente. Vamos a darle esa responsabilidad al jugador. Sustituye la clase del capítulo anterior por esta versión:

    Jugador.java

    public class Jugador {
    String nombre;
    int puntos;

    public void sumarPuntos(int cantidad) {
        puntos += cantidad;
    }

    public int consultarPuntos() {
        return puntos;
    }

    public boolean haGanado() {
        return puntos >= 100;
    }

    public void cambiarNombre(String nombre) {
        this.nombre = nombre;
    }
}

    Leer la cabecera de un método

    Parte Significado en public int consultarPuntos()
    public Podemos llamarlo desde otras clases.
    int Devuelve un valor entero.
    consultarPuntos Nombre de la operación.
    () No necesita parámetros.

    En sumarPuntos(int cantidad), el parámetro es la variable que recibe el dato. En j1.sumarPuntos(20), el argumento es el valor concreto 20. El parámetro solo existe dentro de esa llamada al método.

    void significa que el método no devuelve un valor. Un método con tipo de retorno devuelve un valor compatible mediante return. Esa instrucción termina la ejecución de la llamada.

    Llamar y aprovechar el resultado

    Dentro de main

    Jugador j1 = new Jugador();
j1.cambiarNombre("Ana");
j1.sumarPuntos(60);
j1.sumarPuntos(40);
int total = j1.consultarPuntos();
System.out.println(total);
if (j1.haGanado()) {
    System.out.println("Ha ganado");
}

    El resultado es 100 y después «Ha ganado». Llamar a un método que devuelve un valor no lo muestra automáticamente. Para verlo usamos System.out.println; para tomar una decisión podemos usarlo en un if.

    this: el objeto que recibe la llamada

    En cambiarNombre el atributo y el parámetro se llaman igual. this.nombre identifica el atributo del objeto; nombre identifica el parámetro. Si llamamos a j1.cambiarNombre("Ana"), this se refiere al objeto de j1.

    nombre = nombre; asignaría el parámetro a sí mismo: el atributo no cambiaría. Cuando no hay coincidencia de nombres, escribir this suele ser opcional.

    Varios parámetros

    Método que puedes añadir a Jugador

    public int calcularPuntosExtra(int aciertos, int puntosPorAcierto) {
    return aciertos * puntosPorAcierto;
}

    Dentro de main

    int extra = j1.calcularPuntosExtra(3, 5);
j1.sumarPuntos(extra);

    Los argumentos deben coincidir en número, orden y tipos con los parámetros. Este cálculo devuelve 15; solo la llamada posterior a sumarPuntos modifica el estado. Una variable declarada dentro de un método es local a ese método.

    Comprueba tu comprensión

    Jugador a = new Jugador();
Jugador b = new Jugador();
a.sumarPuntos(10);
b.sumarPuntos(3);
boolean resultado = a.haGanado();

    ¿Qué puntos tiene cada objeto? ¿Consultar haGanado modifica los puntos?

    Ver solución orientativa

    a tiene 10, b tiene 3 y resultado vale false. haGanado consulta el estado sin modificarlo.

    ¿Main o el objeto?

    El objeto realiza las operaciones que dependen de su estado. Main coordina: crea objetos, llama a sus métodos y muestra resultados. Para reutilizar nuestras clases, evitaremos mezclar cada operación con preguntas por teclado.

    Practica

    • Añade reiniciarPuntos(), sin parámetros ni retorno.
    • Añade estaPorDelanteDe(int otrosPuntos), que devuelva boolean.
    • Prueba 0, 99 y 100 puntos y anota el resultado esperado de haGanado antes de ejecutar.
    • Crea Termostato con temperatura actual y objetivo: incluye un método para cambiar el objetivo y otro para consultar si hace falta calentar. No uses entrada por teclado dentro de la clase.

    Recuerda

    • Los parámetros reciben los argumentos de cada llamada.
    • void no devuelve un valor; return permite devolver un resultado.
    • this identifica el objeto actual y ayuda a distinguir atributos y parámetros.
    • Main coordina; cada objeto gestiona su propio comportamiento.

    4.3 Constructores e inicialización

    Crear un objeto incluye darle un estado inicial coherente. El constructor nos permite exigir los datos que necesita.

    Que el objeto nazca preparado

    Con new Jugador() podíamos olvidar asignar el nombre. Un constructor recibe los datos iniciales y prepara el objeto al crearlo. Sustituye Jugador por:

    Jugador.java

    public class Jugador {
    String nombre;
    int puntos;

    public Jugador(String nombre) {
        this.nombre = nombre;
        this.puntos = 0;
    }

    public Jugador(String nombre, int puntos) {
        this.nombre = nombre;
        this.puntos = puntos;
    }

    public void sumarPuntos(int cantidad) {
        puntos += cantidad;
    }

    public int consultarPuntos() {
        return puntos;
    }
}

    Dentro de main

    Jugador ana = new Jugador("Ana");
Jugador iker = new Jugador("Iker", 20);
System.out.println(ana.consultarPuntos());
System.out.println(iker.consultarPuntos());

    Ana empieza con 0 puntos e Iker con 20. Java elige el constructor según los argumentos de la llamada: eso es una forma sencilla de sobrecarga.

    Cómo reconocer un constructor

    • Tiene exactamente el nombre de la clase.
    • No tiene tipo de retorno, ni siquiera void.
    • Se ejecuta al crear el objeto con new.
    • Puede asignar atributos y comprobar los datos iniciales.
    Si escribes public void Jugador(...) , has declarado un método, no un constructor.

    El constructor por defecto

    Cuando no declaramos ningún constructor, Java proporciona uno sin parámetros. En cuanto declaramos un constructor propio, Java deja de añadirlo. Por eso new Jugador() ya no compila con esta versión: solo existen los constructores que hemos escrito.

    Si de verdad necesitamos construir sin datos, debemos definir explícitamente un constructor sin parámetros y decidir unos valores iniciales adecuados. Tener muchos constructores no hace mejor una clase; deben responder a necesidades reales.

    Validar desde el principio

    Para impedir puntos iniciales negativos podemos sustituir el segundo constructor por:

    public Jugador(String nombre, int puntos) {
    if (nombre == null || nombre.isBlank()) {
        throw new IllegalArgumentException("El nombre es obligatorio");
    }
    if (puntos < 0) {
        throw new IllegalArgumentException("Los puntos no pueden ser negativos");
    }
    this.nombre = nombre;
    this.puntos = puntos;
}

    El operador || evita evaluar isBlank cuando nombre es null. Ante un dato no válido se lanza una excepción, como vimos en la unidad anterior. La creación no se completa normalmente: no obtenemos un jugador válido de esa llamada.

    Las mismas reglas deben aplicarse al constructor de un parámetro. Una forma de evitar repetirlas es encadenar los constructores:

    public Jugador(String nombre) {
    this(nombre, 0);
}

    this(nombre, 0) llama al otro constructor de la misma clase. En Java 17 debe ser la primera instrucción del constructor. No lo confundas con this.nombre, que accede a un atributo.

    Comprueba tu comprensión

    ¿Cuántos objetos crea this(nombre, 0)? ¿Por qué new Jugador("Ana", -1) no debe producir un jugador utilizable?

    Ver solución orientativa

    No crea un segundo objeto: ambos constructores colaboran en la inicialización del mismo. La segunda llamada recibe datos no válidos y lanza una excepción.

    Practica

    • Crea Marcador con nombre y valor entero no negativo. Define un constructor de dos parámetros y otro que empiece en cero.
    • Prueba un valor positivo, cero y un valor negativo. Comprueba también nombre null y nombre vacío.
    • Crea Rectangulo con ancho y alto positivos. Ofrece un constructor para dos medidas y otro para un cuadrado. Añade calcularArea().
    • Explica por qué un constructor no sustituye a un método como sumarPuntos: inicializar y modificar son momentos diferentes.

    Recuerda

    • Un constructor se llama como la clase y no declara retorno.
    • Varios constructores pueden ofrecer distintas formas de inicialización.
    • Java solo añade un constructor por defecto si no hemos declarado ninguno.
    • La validación inicial impide construir objetos con datos no admitidos.

    4.4 Encapsulación y diseño de clases

    Los atributos privados y los métodos adecuados permiten mantener el estado del objeto dentro de las reglas del problema.

    Proteger las reglas del objeto

    Aunque el constructor valide, todavía podríamos escribir j.puntos = -500; desde Main. Necesitamos controlar todos los cambios. Encapsular consiste en proteger el estado y ofrecer operaciones que respeten las reglas.

    Jugador.java: nueva versión completa

    public class Jugador {
    private String nombre;
    private int puntos;

    public Jugador(String nombre) {
        this(nombre, 0);
    }

    public Jugador(String nombre, int puntos) {
        if (nombre == null || nombre.isBlank() || puntos < 0) {
            throw new IllegalArgumentException("Datos de jugador no válidos");
        }
        this.nombre = nombre;
        this.puntos = puntos;
    }

    public String getNombre() {
        return nombre;
    }

    public int getPuntos() {
        return puntos;
    }

    public void setNombre(String nombre) {
        if (nombre == null || nombre.isBlank()) {
            throw new IllegalArgumentException("El nombre es obligatorio");
        }
        this.nombre = nombre;
    }

    public boolean sumarPuntos(int cantidad) {
        if (cantidad <= 0) {
            return false;
        }
        puntos += cantidad;
        return true;
    }

    public boolean haGanado() {
        return puntos >= 100;
    }
}

    Ahora j.puntos = -500; no compila desde Main. getPuntos permite consultar y sumarPuntos controla el cambio. Si la cantidad no es positiva, devuelve false y conserva el estado. Main decide cómo avisar de ese resultado.

    Visibilidad mínima que necesitamos

    Modificador Uso
    public Un miembro accesible desde otras clases, siempre que la clase sea accesible.
    private Un miembro accesible dentro de la clase que lo declara.
    Sin modificador Accesible desde clases del mismo paquete.

    Una clase principal de un archivo puede ser public o tener acceso de paquete si no lleva modificador. No puede declararse private como clase de nivel superior. En el capítulo de paquetes veremos por qué la visibilidad también importa para las clases.

    La visibilidad regula el acceso al código. No sustituye a la validación de valores: un método público sigue teniendo que comprobar los datos que recibe.

    Getters, setters y operaciones

    Un getter consulta un atributo; un setter modifica uno, normalmente con validación. No hay que generar un setter por cada atributo. Los puntos se obtienen mediante una acción: por eso preferimos sumarPuntos a permitir cualquier setPuntos.

    Del mismo modo, una cuenta puede ofrecer ingresar y retirar en lugar de setSaldo. Las operaciones expresan qué cambios permite el programa. Una consulta como haGanado calcula un resultado: no necesita guardar un atributo adicional que pueda quedar desactualizado.

    Prueba la protección

    Dentro de main

    Jugador ana = new Jugador("Ana", 10);
boolean aceptada = ana.sumarPuntos(-5);
System.out.println(aceptada);
System.out.println(ana.getPuntos());
ana.setNombre("Ane");
System.out.println(ana.getNombre());

    Predice la salida y compruébala: false, 10, Ane. En el depurador observa que la operación rechazada no modifica los puntos.

    Comprueba tu comprensión

    Un setter acepta cualquier cantidad negativa aunque el constructor la rechace. ¿Está protegida la regla de la clase?

    Ver solución orientativa

    No. Hay que preservar las reglas en todos los caminos que puedan cambiar el estado. El constructor protege el inicio; los métodos protegen los cambios posteriores.

    Practica

    • Crea Deposito con capacidad y litros actuales privados. El constructor exige capacidad positiva y empieza vacío.
    • Añade getLitros(), llenar(int cantidad) y vaciar(int cantidad). Cada operación devuelve boolean y solo acepta cantidades positivas que respeten 0 ≤ litros ≤ capacidad.
    • No añadas setLitros(). Prueba llenar hasta la capacidad exacta, sobrepasarla, vaciar hasta cero y vaciar más de lo disponible.
    • Crea después un Contador entre 0 y un máximo: incluye incrementar y reiniciar. Decide qué consultas necesita Main.

    Recuerda

    • private protege el acceso directo al estado.
    • No todos los atributos necesitan setter.
    • Constructores y métodos deben preservar las mismas reglas.
    • Una operación rechazada debe tener un resultado claro y conservar el estado.

    4.5 Relaciones y colaboración entre objetos

    Un objeto puede recibir, guardar y devolver referencias a otros objetos. Así repartimos el trabajo entre varias clases sin necesitar arrays ni colecciones.

    Un objeto puede conocer a otro

    Una partida necesita saber quién juega. En lugar de copiar el nombre y los puntos, guarda una referencia a un Jugador. Usaremos la versión encapsulada del capítulo anterior.

    Partida.java

    public class Partida {
    private Jugador jugador;
    private boolean terminada;

    public Partida(Jugador jugador) {
        if (jugador == null) {
            throw new IllegalArgumentException("Se necesita un jugador");
        }
        this.jugador = jugador;
        this.terminada = false;
    }

    public Jugador getJugador() {
        return jugador;
    }

    public boolean estaTerminada() {
        return terminada;
    }

    public boolean registrarAcierto(int puntos) {
        if (terminada) {
            return false;
        }
        boolean aceptado = jugador.sumarPuntos(puntos);
        if (aceptado && jugador.haGanado()) {
            terminada = true;
        }
        return aceptado;
    }
}

    Dentro de main

    Jugador ana = new Jugador("Ana");
Partida partida = new Partida(ana);
partida.registrarAcierto(60);
partida.registrarAcierto(40);
System.out.println(ana.getPuntos());
System.out.println(partida.estaTerminada());
System.out.println(partida.getJugador().getNombre());

    La salida es 100, true, Ana. Partida controla si se puede jugar; Jugador controla sus puntos. Cada clase tiene una responsabilidad. Partida contiene una referencia, no una copia independiente del jugador.

    Seguir las llamadas

    • Main pide registrarAcierto a Partida.
    • Partida comprueba que no haya terminado.
    • Partida pide sumarPuntos a su Jugador.
    • Partida consulta si ha ganado y actualiza su propio estado.
    • Main consulta y presenta los resultados.

    La expresión partida.getJugador().getNombre() primero obtiene el jugador y después consulta su nombre. Para entenderla podemos separarla:

    Jugador participante = partida.getJugador();
String nombre = participante.getNombre();

    Referencias compartidas

    Jugador participante = partida.getJugador();
participante.setNombre("Ane");
System.out.println(ana.getNombre());

    ¿Qué nombre aparece?

    Ver solución orientativa

    Ane. ana, participante y el atributo jugador de partida apuntan al mismo objeto. getJugador devuelve esa referencia.

    Devolver un objeto permite utilizar sus métodos públicos. Un atributo private no convierte al objeto referido en una copia ni impide que otras referencias lo modifiquen.

    Esta pequeña Partida supone que los puntos se modifican a través de registrarAcierto mientras se juega. Si Main llama directamente a sumarPuntos, puede cambiar los puntos sin actualizar terminada. Es una decisión de uso que debemos respetar; más adelante aprenderemos diseños que controlan mejor este tipo de cambios.

    Recibir y devolver objetos

    Un atributo, un parámetro o el retorno de un método puede tener el tipo de una clase propia. Por ejemplo, un Coche puede recibir un propietario en su constructor y permitir cambiarlo:

    Fragmento para una clase Coche con atributo Persona propietario

    public void cambiarPropietario(Persona nuevoPropietario) {
    if (nuevoPropietario == null) {
        throw new IllegalArgumentException("Se necesita un propietario");
    }
    this.propietario = nuevoPropietario;
}

    Cambiar la referencia no modifica la Persona anterior: el coche pasa a conocer a otra. Si una relación es obligatoria, rechazamos null. Si fuese opcional, habría que comprobarlo antes de utilizarla.

    Practica con dos clases

    • Crea Persona con nombre privado, constructor validado y getNombre().
    • Crea Coche con matrícula y una Persona propietaria. Ambas son obligatorias. Añade getMatricula(), getPropietario() y cambiarPropietario().
    • Crea dos personas y un coche. Cambia su propietario y muestra el nombre antes y después.
    • Comprueba que recibir null como propietario no altera el propietario actual.

    Transferencia

    Diseña Habitacion con número y precio por noche positivo, Cliente con nombre y Reserva con una habitación, un cliente y un número positivo de noches. Reserva calcula el total utilizando el precio de su habitación. Solo necesitamos una reserva y variables individuales.

    Ver solución orientativa

    Reserva recibe Cliente y Habitacion en el constructor y guarda sus referencias. calcularTotal() puede devolver habitacion.getPrecioPorNoche() * noches. No necesita guardar una copia del nombre del cliente ni del precio si quiere consultar siempre los datos actuales.

    Recuerda

    • Una clase puede utilizar otras clases como tipos de atributos, parámetros y retornos.
    • Guardar o devolver una referencia no copia el objeto.
    • Cada clase debe encargarse de sus propias reglas.
    • Las relaciones obligatorias deben inicializarse y protegerse frente a null.

    4.6 Miembros de clase: static y constantes

    Algunos datos y operaciones pertenecen a un objeto; otros se comparten a través de la clase. static nos permite expresar esa diferencia.

    Datos del objeto y datos de la clase

    Cada jugador tiene sus puntos. Sin embargo, podemos contar cuántos jugadores hemos creado durante la ejecución. Ese contador se comparte entre las instancias y pertenece a la clase.

    Jugador.java: versión independiente para este capítulo

    public class Jugador {
    public static final int PUNTOS_PARA_GANAR = 100;
    private static int jugadoresCreados = 0;

    private String nombre;
    private int puntos;

    public Jugador(String nombre) {
        if (nombre == null || nombre.isBlank()) {
            throw new IllegalArgumentException("El nombre es obligatorio");
        }
        this.nombre = nombre;
        puntos = 0;
        jugadoresCreados++;
    }

    public static int getJugadoresCreados() {
        return jugadoresCreados;
    }

    public String getNombre() {
        return nombre;
    }

    public int getPuntos() {
        return puntos;
    }

    public boolean sumarPuntos(int cantidad) {
        if (cantidad <= 0) {
            return false;
        }
        puntos += cantidad;
        return true;
    }

    public boolean haGanado() {
        return puntos >= PUNTOS_PARA_GANAR;
    }
}

    Dentro de main

    Jugador ana = new Jugador("Ana");
Jugador iker = new Jugador("Iker");
ana.sumarPuntos(10);
System.out.println(ana.getPuntos());
System.out.println(iker.getPuntos());
System.out.println(Jugador.getJugadoresCreados());
System.out.println(Jugador.PUNTOS_PARA_GANAR);

    Muestra 10, 0, 2 y 100. Los puntos son independientes; jugadoresCreados es compartido. Llamamos a los miembros estáticos mediante el nombre de la clase.

    El contador registra construcciones válidas, no jugadores que siguen vivos ni jugadores conectados. Si hacemos Jugador otra = ana; , no aumenta. Al reiniciar el programa vuelve a empezar en cero.

    Qué significa static

    Miembro Cómo se utiliza
    Atributo de instancia Cada objeto tiene su propio valor.
    Atributo static Existe un valor compartido asociado a la clase.
    Método de instancia Se llama sobre un objeto y puede utilizar su estado.
    Método static Se llama sobre la clase; no tiene un objeto this.

    Un método static no puede acceder directamente a nombre o puntos: ¿los de qué jugador? Sí puede usar parámetros, variables locales y miembros estáticos. Por eso desde main creamos un objeto antes de llamar a sus métodos de instancia.

    Constantes

    final impide reasignar ese campo después de su inicialización. En public static final int PUNTOS_PARA_GANAR = 100; combinamos acceso público, un valor de clase y una constante. Los nombres de constantes suelen escribirse con mayúsculas y guiones bajos.

    Un método estático de utilidad

    Conversor.java

    public class Conversor {
    public static double minutosAHoras(int minutos) {
        if (minutos < 0) {
            throw new IllegalArgumentException("Los minutos no pueden ser negativos");
        }
        return minutos / 60.0;
    }
}

    Dentro de main

    System.out.println(Conversor.minutosAHoras(90));

    Devuelve 1.5. El cálculo no depende del estado de ningún Conversor. Usamos 60.0 para evitar la división entera.

    Comprueba y practica

    Creamos dos jugadores y hacemos Jugador tercero = ana;. ¿Qué devuelve getJugadoresCreados?

    Ver solución orientativa

    2. Hay tres variables, pero solo dos construcciones.

    • Añade a Conversor un método estático para pasar horas a minutos.
    • Diseña una clase Entrada con precio de instancia y un contador estático de entradas creadas. Construye dos y compara sus precios con el contador.
    • Explica por qué no debes declarar static los puntos de Jugador.

    Recuerda

    • static asocia el miembro a la clase.
    • Un método estático no tiene this.
    • static final es adecuado para constantes compartidas.
    • Una referencia adicional a un objeto no cuenta como una nueva construcción.

    4.7 Organización y reutilización de clases

    Los paquetes ordenan nuestras clases. Una pequeña biblioteca en código fuente nos permite reutilizar lo que ya hemos programado.

    Organizar un proyecto

    Cuando aparecen varias clases, los paquetes ayudan a agruparlas. Un paquete es un nombre que organiza clases; no es un array ni una colección de objetos. Vamos a separar el modelo de la aplicación.

    Ruta de archivo Primera instrucción
    src/modelo/Jugador.java package modelo;
    src/modelo/Partida.java package modelo;
    src/app/Main.java package app;

    En el IDE crea los paquetes dentro de la carpeta de fuentes de tu proyecto. Si trabajáis con Maven, esa carpeta suele ser src/main/java. Mantén una clase pública por archivo y el nombre de archivo correspondiente.

    package e import

    src/modelo/Jugador.java: ejemplo mínimo

    package modelo;

public class Jugador {
    private String nombre;

    public Jugador(String nombre) {
        if (nombre == null || nombre.isBlank()) {
            throw new IllegalArgumentException("El nombre es obligatorio");
        }
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }
}

    src/app/Main.java

    package app;

import modelo.Jugador;

public class Main {
    public static void main(String[] args) {
        Jugador jugador = new Jugador("Ana");
        System.out.println(jugador.getNombre());
    }
}

    package indica a qué paquete pertenece la clase. import permite utilizar su nombre corto desde otro paquete. No crea objetos ni ejecuta la clase. También podríamos escribir modelo.Jugador con el nombre completo.

    Visibilidad entre paquetes

    Para usar Jugador desde app, la clase, el constructor y getNombre son públicos. Si quitamos public a la clase, solo podrá usarse desde modelo. Si quitamos public a getNombre, ese método solo será accesible desde modelo. Los atributos privados siguen protegidos incluso dentro del mismo paquete.

    Una clase no puede importar y usar cualquier otra solo por conocer su nombre. Debe estar disponible en el proyecto y su visibilidad debe permitir el acceso.

    Crear una pequeña biblioteca reutilizable

    Una biblioteca es un conjunto de clases que podemos reutilizar. Para empezar crearemos una biblioteca en código fuente, sin generar archivos JAR ni introducir herramientas nuevas.

    • Crea un paquete utilidades con Conversor.java del capítulo anterior. Cambia su primera línea a package utilidades;.
    • En app.Main escribe import utilidades.Conversor; y utiliza minutosAHoras(90).
    • Crea un segundo proyecto de consola, copia el paquete utilidades en su carpeta de fuentes e importa Conversor desde su Main.
    • Comprueba que la misma clase funciona sin modificarla en el segundo programa.

    Así hemos creado y utilizado un conjunto de clases reutilizables. No basta con organizar carpetas: la reutilización se comprueba empleando nuestras clases en otro programa.

    Bibliotecas de Java

    import java.util.Scanner;

    Scanner es una clase de la biblioteca estándar que ya hemos utilizado. Clases como String y Math están en java.lang y no necesitan import explícito. También podemos usar Math.abs(-7), que devuelve 7 mediante un método estático.

    Comprueba tu comprensión

    ¿Es import modelo.Jugador; equivalente a new Jugador("Ana")?

    Ver solución orientativa

    No. import resuelve el nombre de la clase en el código. new crea un objeto durante la ejecución.

    Practica

    • Organiza Cliente, Habitacion y Reserva en modelo y Main en app.
    • Muestra desde Main el cliente de una reserva utilizando sus métodos públicos.
    • Copia el paquete utilidades en ese proyecto y usa Conversor para mostrar en horas una duración en minutos.
    • Quita temporalmente public a una clase y a un método utilizados desde app. Lee los errores del compilador y restaura el acceso necesario.

    Recuerda

    • package organiza clases e import permite usar sus nombres cortos.
    • La visibilidad también afecta a clases, constructores y métodos entre paquetes.
    • Una biblioteca puede empezar como un conjunto reutilizable de archivos fuente.
    • Importar una clase no equivale a crear un objeto.

    4.8 Primera aproximación a herencia e interfaces

    Vamos a reconocer y utilizar dos mecanismos de reutilización con ejemplos mínimos y separados del trabajo principal de la unidad.

    Este capítulo es una primera aproximación. Practicaremos una clase heredada y una interfaz sencillas; el desarrollo de herencia y polimorfismo llegará en una unidad posterior.

    Herencia: una clase a partir de otra

    Una Persona tiene nombre. Un Alumno también es una Persona y añade un curso. Podemos reutilizar la parte común mediante extends. Crea un proyecto pequeño con estos tres archivos en el mismo paquete:

    Persona.java

    public class Persona {
    private String nombre;

    public Persona(String nombre) {
        if (nombre == null || nombre.isBlank()) {
            throw new IllegalArgumentException("El nombre es obligatorio");
        }
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }
}

    Alumno.java

    public class Alumno extends Persona {
    private String curso;

    public Alumno(String nombre, String curso) {
        super(nombre);
        if (curso == null || curso.isBlank()) {
            throw new IllegalArgumentException("El curso es obligatorio");
        }
        this.curso = curso;
    }

    public String getCurso() {
        return curso;
    }
}

    Main.java

    public class Main {
    public static void main(String[] args) {
        Alumno alumno = new Alumno("Ana", "DAW1");
        System.out.println(alumno.getNombre());
        System.out.println(alumno.getCurso());
    }
}

    extends Persona indica que Alumno hereda de Persona. super(nombre) llama al constructor de Persona para inicializar esa parte del objeto. Los constructores no se heredan: Alumno define el suyo.

    getNombre está definido en Persona y puede utilizarse sobre un Alumno. El atributo nombre sigue siendo privado: Alumno no accede directamente a él. No necesitamos cambiarlo a protected.

    No confundas relaciones: un Alumno es una Persona; un Coche tiene una Persona propietaria. En el segundo caso usamos un atributo, como en el capítulo 4.5.

    Interfaces: una operación que hay que ofrecer

    Queremos indicar que una clase debe ofrecer una operación imprimir. Una interfaz declara esa operación y la clase escribe cómo se realiza.

    Imprimible.java

    public interface Imprimible {
    void imprimir();
}

    Ticket.java

    public class Ticket implements Imprimible {
    private String concepto;

    public Ticket(String concepto) {
        if (concepto == null || concepto.isBlank()) {
            throw new IllegalArgumentException("El concepto es obligatorio");
        }
        this.concepto = concepto;
    }

    @Override
    public void imprimir() {
        System.out.println("Ticket: " + concepto);
    }
}

    Dentro de main

    Ticket ticket = new Ticket("Entrada al museo");
ticket.imprimir();

    implements indica que Ticket cumple la interfaz. El método de esta interfaz es público y abstracto de forma implícita: declara qué hay que hacer, sin cuerpo. Ticket debe implementarlo como public. @Override permite al compilador comprobar que estamos implementando el método declarado.

    Aquí imprimir significa mostrar en la consola. No enviamos nada a una impresora ni trabajamos con ficheros o interfaz gráfica.

    Qué ocurre si falta el método

    Borra temporalmente imprimir de Ticket. El compilador avisará de que la clase no cumple la interfaz. Restaura el método y ejecuta. También falla si cambias el nombre a mostrar o quitas public.

    Practica lo mínimo

    • Define Profesor extends Persona con un atributo especialidad y su constructor. Crea un Profesor y llama a getNombre() y getEspecialidad().
    • Define una interfaz Describible con String describir();.
    • Crea Tarjeta implements Describible, con un texto recibido por constructor. Implementa describir para devolver ese texto. Crea una Tarjeta y muestra el resultado.
    • Utiliza variables Profesor y Tarjeta. En esta introducción no necesitamos variables del tipo padre ni del tipo interfaz.

    Comprueba tu comprensión

    ¿Para qué sirve super(nombre)? ¿La interfaz escribe el mensaje concreto de Ticket?

    Ver solución orientativa

    super(nombre) inicializa la parte Persona llamando a su constructor. La interfaz declara imprimir; Ticket decide cómo producir el mensaje.

    Recuerda

    • extends permite definir una clase heredada y utilizar métodos accesibles del padre.
    • super(...) llama al constructor del padre.
    • implements obliga a ofrecer las operaciones de una interfaz.
    • Aquí trabajamos la definición y el uso básico; profundizaremos más adelante.

    4.9 Diseño e integración de programas orientados a objetos

    Aplicaremos lo aprendido a un problema conocido y después a otros contextos. La dificultad está en decidir qué debe hacer cada clase.

    Del enunciado al programa

    Programar con clases empieza antes de escribir código. Lee el problema, identifica los datos y las acciones y decide qué objeto se responsabiliza de cada una.

    • Subraya los elementos que tienen identidad o datos propios: posibles clases.
    • Anota qué información necesita cada elemento: posibles atributos.
    • Identifica las acciones y consultas: posibles métodos.
    • Decide qué datos exige cada constructor y qué reglas deben mantenerse.
    • Dibuja o escribe qué objeto necesita conocer a otro.
    • Crea un Main pequeño y comprueba un caso antes de añadir el siguiente.
    Los sustantivos son pistas, no una regla automática. No hace falta crear una clase para cada palabra del enunciado.

    Práctica guiada: una sesión de juego

    Una sesión tiene un jugador y una duración positiva en minutos. El jugador empieza con cero puntos. Se pueden registrar aciertos con una cantidad positiva de puntos, hasta alcanzar 100. Al terminar la partida, no se aceptan nuevos aciertos. Queremos mostrar el nombre, los puntos y la duración en horas.

    Clase Responsabilidad
    Jugador Guardar nombre y puntos, sumar una cantidad válida y consultar si ha ganado.
    Partida Guardar el jugador, la duración y si ha terminado; aceptar aciertos mientras siga activa.
    Conversor Convertir minutos a horas mediante un método estático.
    Main Crear objetos, realizar llamadas y mostrar resultados.

    Organiza las clases en modelo, utilidades y app. Parte de las clases de 4.5 y 4.6. Para trabajar paso a paso, añade a Partida un atributo privado duracionMinutos, recíbelo como segundo parámetro del constructor y valida que sea positivo.

    Objetivo para Main, con los imports correspondientes

    Jugador ana = new Jugador("Ana");
Partida partida = new Partida(ana, 90);
System.out.println(partida.registrarAcierto(60));
System.out.println(partida.registrarAcierto(40));
System.out.println(partida.registrarAcierto(5));
System.out.println(partida.getJugador().getPuntos());
System.out.println(partida.estaTerminada());
System.out.println(Conversor.minutosAHoras(90));

    Antes de ejecutar, escribe los resultados esperados.

    Ver solución orientativa

    true, true, false, 100, true y 1.5. La tercera operación no cambia los puntos porque la partida ya terminó.

    Comprueba varios casos

    Caso Resultado esperado
    Acierto de 0 o negativo false; mismos puntos; partida no termina por esa llamada.
    Llegar a 99 puntos Partida todavía activa.
    Llegar a 100 o superar 100 Partida terminada.
    Registrar después del final false; puntos sin cambios.
    Duración 0 o jugador null El constructor rechaza la creación.

    Prueba cada caso con un jugador y una partida nuevos cuando necesites empezar desde cero. Comprueba tanto el resultado de la operación como el estado posterior.

    Ahora diseña tú: una reserva de habitación

    Un cliente tiene nombre obligatorio. Una habitación tiene número positivo y precio por noche positivo, expresado en euros enteros para simplificar. Una reserva relaciona un cliente y una habitación durante un número positivo de noches. Puede cancelarse una sola vez. Mientras está activa, su importe es precio por noche multiplicado por noches; si está cancelada, el importe es cero.

    • Define Cliente, Habitacion y Reserva. Decide sus atributos privados y los constructores.
    • Ofrece los getters necesarios, calcularImporte(), estaCancelada() y cancelar(). cancelar devuelve true solo cuando realiza la cancelación.
    • No permitas null en cliente ni habitación. Para esta práctica, el precio no cambia después de construir la habitación.
    • Crea una reserva de 3 noches a 60 euros. Muestra el cliente y comprueba que el importe sea 180.
    • Cancela, vuelve a consultar el importe y realiza una segunda cancelación.
    • Organiza las clases y reutiliza una utilidad estática propia en Main, por ejemplo para calcular un descuento porcentual del importe activo.
    Ver solución orientativa

    Reserva guarda referencias a Cliente y Habitacion, un int noches y un boolean cancelada. El cálculo pertenece a Reserva; getNombre pertenece a Cliente. La primera cancelación devuelve true y deja el importe en 0; la segunda devuelve false.

    Transferencia: un envío

    Sin copiar los nombres de las clases anteriores, diseña un envío con destinatario, dirección y peso positivo en gramos. La dirección tiene calle y localidad obligatorias. El precio es una base de 4 euros más 2 euros por cada kilogramo iniciado. Un envío puede marcarse entregado una sola vez.

    • Identifica tres clases del modelo y escribe sus responsabilidades antes de programar.
    • Relaciona los objetos mediante atributos de tipos propios. No repitas calle y localidad en Envio.
    • Ofrece calcularPrecio() y marcarEntregado(), además de las consultas necesarias.
    • Prueba pesos de 1, 1000 y 1001 gramos: deben costar 6, 6 y 8 euros.
    • Para calcular kilogramos iniciados puedes usar (pesoGramos - 1) / 1000 + 1, tras validar que el peso sea positivo.
    • Comprueba que marcar entregado dos veces devuelve true y después false.

    Revisa tu diseño

    • ¿Cada clase tiene una responsabilidad clara?
    • ¿Los atributos están protegidos y las reglas se cumplen desde el constructor?
    • ¿Los métodos devuelven información útil para Main?
    • ¿Entiendes cuándo compartes una referencia y cuándo creas otro objeto?
    • ¿Puedes explicar por qué una operación es de instancia o estática?
    • ¿Has probado casos normales, límites y rechazados?

    No añadas herencia o interfaces por obligación a estos diseños. Para repasar la introducción del capítulo 4.8, utiliza sus ejercicios específicos. Aquí el objetivo es construir y hacer colaborar clases sencillas.

    Recuerda

    • Diseñar significa repartir datos y responsabilidades.
    • Un problema nuevo puede resolverse con las mismas técnicas de clases y referencias.
    • Comprueba el estado posterior además del valor devuelto por cada operación.
    • Empieza por un caso pequeño y añade las reglas de forma gradual.
